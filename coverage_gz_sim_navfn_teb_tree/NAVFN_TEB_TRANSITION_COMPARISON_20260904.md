# Navfn+TEB 与 Hybrid A*+TEB 线间转场配对仿真（2026-09-04）

## 结论

当前直接 Hybrid A* + 固定档位 TEB 架构明显优于“所有线间转场均使用
Navfn+TEB、TEB 前视 8 m”的对照架构。两者都完成了同一长条区域，但对照架构的三次
换线总时间为 `308.510 s`，当前架构把一次入口恢复异常也计入后为 `55.498 s`；前者约为
后者的 5.56 倍。对照架构累计停车约 `166.184 s`、实走 `26.091 m`，而当前架构分别为
约 `7.200 s` 和 `12.019 m`。

Navfn 本身每秒都能重新给出接近二维最短路的短全局路径，失败发生在 TEB 如何用
Ackermann 车辆完成终点姿态：它反复前进、倒车和停车，并没有把二维路径转换成稳定的
最小半径调头轨迹。8 m 前视还使 10 Hz 控制循环大量降到约 0.4--2 Hz，局部轨迹相对
Navfn 全局路径的 P95 最大偏差达到 `1.040 m`。因此不建议把该架构同步到实车。

## 单变量设置

对比树从当前 `coverage_gz_sim_tree` 完整复制源码与配置，只增加内部参数
`navfn_all_swath_transitions=true`，使区内后续换线与首线一样使用
`MODE_COVERAGE_NAVFN`。同时按实验要求把普通 TEB 与覆盖管理器动态配置的
`max_global_plan_lookahead_dist` 都设为 `8.0 m`。

下列项目两边一致：

- 地图：`global_maps/map_sets/latest -> map_20260827_184123`；
- 区域：昨日第二轮实车长条四边形；
- 初值：`(15.84, -20.58, -1.603 rad)`；
- M2：轴距 `0.65 m`、最小转弯半径 `1.35 m`；
- 车体与导航包络：`1.04 x 0.70 m`，审计包络前后 `0.62 m`、半宽 `0.45 m`；
- 清扫宽度/重叠：`1.00 m / 15%`；
- 速度、倒车速度、角速度、加速度：`0.80 / 0.30 m/s`、`0.60 rad/s`、
  `1.00 m/s^2`、`0.50 rad/s^2`；
- 清扫线排序和方向：`[0,3,1,2]`；
- 真值位姿，无激光、无动态障碍。

当前架构的转场 TEB 前视仍是其原值 `2.0 m`；将对照架构改成 8 m 是用户指定的第二个、
也是除全局转场规划器之外唯一参数差异。

## 完全相同的路线

两轮均按以下四条线执行：

1. 行 0：`(15.668,-20.796) -> (15.295,-32.832)`；
2. 行 3：`(17.824,-33.545) -> (18.212,-21.018)`；
3. 行 1：`(16.516,-20.870) -> (16.138,-33.070)`；
4. 行 2：`(16.981,-33.308) -> (17.364,-20.944)`。

初值已处于首线入口 `0.276 m` 内且航向一致，两边都直接进入第一条清扫线，没有把首线
Navfn 入场混入换线指标。

当前架构的 `55.498 s` 包含第一换线到达后因实测航向 `25.6°` 略超 `25°` 入场门而触发的
一次 `21.000 s`、仅移动 `0.164 m` 的 Hybrid 入口恢复。若只看三个主连接区间，则为
`8.500 / 11.498 / 14.500 s`，合计 `34.498 s`。这个恢复等待仍是当前架构需要继续优化的
残余异常，不能因总体胜出而忽略。

### Navfn+TEB 的三次运动形状

1. 行 0 -> 行 3：Navfn 初始全局路约 `2.82 m`，接近横向短折线；车辆实际走
   `6.177 m`、耗时 `109.502 s`，净转向约 `160.4°`，停车 `70.976 s`。全局路按 1 Hz
   从实时位姿不断缩短，但 TEB 在路径附近反复小幅进退。
2. 行 3 -> 行 1：二维入口间仅约 `1.70--1.98 m`。第一次实际走 `9.654 m` 后仍以
   `132.5°` 航向误差停在入口附近，action 被重试；第二次又走 `4.258 m`。连同重试等待
   共 `161.496 s`，停车约 `84.566 s`，实际轨迹相对端点弦最大偏离 `1.153 m`。
3. 行 1 -> 行 2：二维入口间约 `1.08 m`，车辆实际走 `6.001 m`、耗时 `37.512 s`，
   净转向约 `163.7°`，停车 `10.642 s`。到达门最终在进度约 49%、位置和航向进入区域时
   提前验收，但此前已经多次前后摆动。

### 当前 Hybrid A*+TEB 的三次运动形状

1. 行 0 -> 行 3：主连接为约 `4.20 m` 的全前进左弧，随后补 `0.30 m` 短弧；主区间
   `8.500 s`。因交接时航向只超门 `0.6°`，又发生上述 `21.000 s` 短恢复。
2. 行 3 -> 行 1：`F1.80/R0.60/F1.80`，cusp 后按实时停车位重算为
   `R0.60/F1.80`；共 `11.498 s`。
3. 行 1 -> 行 2：先 `F1.50/R0.90/F1.50`，随后从实时位姿做事件重算直到入口；共
   `14.500 s`。

## 证据与边界

- 当前架构：
  `coverage_gz_sim_tree/results/paired_hybrid_teb_long_strip_near_north_v1_20260904_135859`；
- Navfn 对照：
  `coverage_gz_sim_navfn_teb_tree/results/navfn_teb_8m_long_strip_near_north_v1_20260904_135513`；
- 两轮实际 footprint 均没有进入占用区或未知区，命令曲率都满足 `1.35 m`；
- Navfn 对照审计失败只因 7 次速度反号未经过零速，不是碰撞或曲率违规；
- 本结果使用静态地图和真值位姿，不代表动态障碍或真实定位噪声下的最终验收。

本对比树只用于反事实实验。权威源码同步采用当前 Hybrid 仿真树，不会把
`navfn_all_swath_transitions` 或 8 m 转场前视带入生产。当前 Hybrid 仿真树已同步到
权威源码，本机 Release 构建、936 项工作区测试和静态健康检查通过，并已部署为 J6M
release `20260904_140758`；部署后实车主链保持停止。
