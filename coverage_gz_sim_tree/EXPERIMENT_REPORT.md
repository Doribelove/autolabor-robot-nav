# 全覆盖规划 Gazebo 隔离实验报告（2026-09-02）

> 本文保留 2026-09-02 的历史迭代，其中自定义 Ackermann 跟踪器已经从当前仿真源码删除。
> 当前架构见 [CURRENT_ARCHITECTURE.md](CURRENT_ARCHITECTURE.md)；文中的运动结果不能作为
> TEB 固定档位 action 架构的验收证据。

## 结论

`docs/NAVIGATION_EXPERIMENT_20260901_PATH_PLANNING_ISSUES.md` 对实机问题的主结论是正确的，
本次无动态障碍、真值定位仿真复现了其中三个与传感器无关的核心架构问题：首线入场的
二维路径不可直接保证 Ackermann 可执行性、批量 Hybrid 预计算阻塞多区域任务、
`nav_msgs/Path -> TEB` 接口不能表达硬档位/cusp。后续回归还发现，轻量排序若只优化端点
距离而不给清扫线定向，会把相邻清扫线排成同向，迫使 Ackermann 车辆用接近一整圈的
前进轨迹换行。

“不预先计算整条任务轨迹”是正确方向，但“每秒从当前位姿到最终目标完整 Hybrid 重算，
且不拆 cusp”不是更好的完整方案：长距离搜索超时，滚动版本虽能实时规划和移动，但一旦
所需路径包含倒车换挡，单个 TEB action 仍然失败。推荐的是轻量覆盖分解、长距离二维拓扑、
滚动运动学前缀，以及保留 cusp 零速分段和硬档位执行。最终版本还用一个不生成路径、
不调用静态 A* 的 Dubins 时间代理联合优化清扫线顺序和方向。它完成 A、C 多区域任务，
相对修复前的同向清扫线版本将仿真时长降低 37.36%、实际里程降低 32.89%，并通过实际
车体足迹、曲率和换挡审计。

## 架构根因

1. **规划范围与执行周期耦合。** 覆盖候选排序会为多个候选边同步运行静态 A*/Hybrid，
   完整任务的预计算又在 move_base 进程内完成。区域变大或跨区距离增加时，启动延迟按
   候选数量和搜索空间同时增长，并挤占 costmap/控制回调。
2. **规划权威重复。** 管理器持有完整逻辑转场和档位分段，global planner 又能从当前位姿
   局部修补当前 action。两者的目标范围、缓存和 generation 不一致，路径显示、时间估计和
   实际执行可属于不同代际。
3. **接口丢失车辆语义。** Hybrid 计算了前进/倒车和 cusp，但 `nav_msgs/Path` 只传位姿。
   TEB 收到的是软 via-point 和速度上限，不能把“此边必须倒车、此处必须零速换挡”作为硬约束。
4. **TEB warm-start 与 1 Hz 全路径替换冲突。** 默认 TEB 假设全局路径相对稳定；每秒替换
   全局路径却复用旧弹性带会累积回环。本次 rosbag 中局部 3 m 参考被优化成 215 点、43.3 m。
5. **二维拓扑与运动学目标未分层。** Navfn 适合长距离连通性，Hybrid 适合局部车辆可达性。
   让 Navfn 直接负责带终端航向的首线入口，或让 Hybrid 每秒搜索完整 53 m，都把算法放在了
   不合适的尺度。
6. **action 边界承担了未显式建模的状态。** cusp 零速、档位、清扫线入口/出口进度和重试
   历史散落在多个 action/跟踪器中；重试或切换代际时容易丢失交接事实。
7. **轻量排序曾丢失清扫线方向代价。** 只按几何距离排列端点会让相邻清扫线保持同向；
   对差速车这可能只是原地转向，但对最小半径 1.20 m 的车辆会变成 13–17 m 的近整圆。
   不能为了“不预计算轨迹”连方向代价也删除。

因此，问题并非单纯“模块太多”，而是同一决定有多个权威、长期规划在实时线程同步执行、
以及模块接口没有携带执行所需的档位和生命周期状态。

## 隔离树中的算法改进

- 首条清扫线入场也使用 Hybrid，并按 cusp 分段，避免 Navfn 末端伪原地转向。
- 在线模式不为所有候选预计算 Hybrid。先用确定性几何代价选择清扫角度，再对该角度的
  清扫线运行有界 beam search；边代价是纯内存 Dubins 时间代理，只决定顺序和正反方向，
  不调用栅格 A*、不构造可执行连接。实测这一排序步骤 A 区约 0.009 s、C 区约 0.293 s；
  带静态连接 A* 的旧时间排序在 C 区约需 67 s wall time。
- 长连接先用 Navfn 得到全局拓扑，只对当前约 10 m 前缀生成运动学 Hybrid；前缀在 action
  边界或偏离/失效时更新，不做无条件 1 Hz 全局路径替换。
- Hybrid 输出按 0.1 m 碰撞采样密化，避免 TEB 在稀疏点间抄近路。
- TEB Twist 输出增加 1.20 m 硬曲率投影，禁止 Ackermann 伪原地旋转。
- 静态障碍只把轨迹相关范围内的墙体边界送入 TEB；近车区域保持地图原分辨率，完整
  costmap 仍负责最终 footprint 可行性检查。
- 已由 Hybrid 指定拓扑的连接段使用单同伦类、较小 TEB 迭代预算。
- 在线 1 Hz 模式收到新全局路径时清空旧 TEB warm-start；基线模式保持原行为。
- 推荐模式把每个 cusp 拆成固定档位 action，Hybrid 段由小型纯跟踪 Ackermann 控制器执行；
  跟踪器拒绝混合档位路径，并硬限制曲率、加速度、换挡边界零速和位姿新鲜度。TEB 继续执行
  清扫线，不再二次改写已通过碰撞检查的 Hybrid 拓扑。
- 每轮结束自动从 bag 回放实际里程计和所有唯一 Hybrid 固定档位路径，用项目有效车体包络
  对 latest 静态图做占用/未知栅格审计，同时检查最小转弯半径和非零速换挡。
- 清扫 action 之前增加 0.30 m / 0.40 rad 硬交接门；超差时保持 `TRANSITING`，用倒车
  代价较低的 Hybrid 重新捕获原入口。恢复候选总长限制 4.0 m、累计前进限制 1.20 m，
  从算法上拒绝“大幅前进绕圈调姿”。

这些修改解决了首线运动学、长距离规划规模、硬曲率和 TEB 轨迹累积问题，但刻意保留的
“不拆 cusp”最终仍失败，说明 cusp 分段不是可以删掉的偶然复杂度。

## 推荐落地架构

```text
区域多边形 -> 几何选角 + 无路径 Dubins 时间代理排序/定向
             （不做整任务 Hybrid 轨迹）
          -> 当前逻辑目标与唯一 generation
          -> 长距离 Navfn/栅格拓扑
          -> 8–12 m 滚动 Hybrid 运动学前缀（1 Hz 检查/更新）
          -> 按 cusp 分成带硬档位的短执行段
          -> Ackermann 跟踪器或带硬档位约束的 TEB
          -> 硬曲率、footprint、零速换挡和进度交接门
```

1 Hz 应作为滚动前缀的更新/有效性检查频率，不应无条件从头搜索完整跨区路径；若当前前缀
仍安全且车辆没有偏离，应保持路径代际和控制连续性。没有原生带档位控制器之前必须继续
拆 cusp；若以后控制器能直接消费带符号 Reeds-Shepp 路径，才可以在一个 action 内执行，
但零速换挡和速度符号仍需是硬约束。

当前隔离实现为减少改动，仍让 move_base/TEB 维持 action 生命周期，再通过命令复用器接管
Hybrid 段。因此旁路 TEB 偶尔会对自己生成、但不会下发的轨迹打印 footprint/oscillation
警告。生产落地时应把固定档位跟踪器实现成正式 local planner/controller 接口，消除双控制器
并行计算；本实验以最终 `/cmd_vel_sim` 和真值足迹审计作为执行结论，而不是忽略真实碰撞。

## 人为异常注入后的架构补充

最终清扫线定向版本又进行了三类人工异常回归：

- 交接边界内样本实测横偏 0.276 m、航向误差 21.90°，0.208 s 后直接启动清扫，没有
  recovery，也没有画圈；A 区完成率 99.20%。
- 正偏航超差样本实测横偏 0.437 m、航向误差 27.48°，始终未进入 `SWEEPING`；规划
  “前进右弧 0.90 m -> 倒车右弧 0.90 m”，实际前进 0.889 m、倒车 0.616 m，故障后
  8.174 s 启动原清扫线。负偏航样本在旧倒车 action 尚在执行时注入，0.302 s 后取消
  旧路径，规划“倒车左弧 0.60 m -> 前进左弧 0.60 m”，实际倒车 0.530 m、前进
  0.397 m，8.200 s 后启动原清扫线。两组均 A 8/8 完成，没有大幅前进绕圈。
- 0.55 m/s 强制冲线在撤销强制控制时已超出 0.475 m，制动后最大超出 0.654 m。完成门
  只在实速为零时交接，未倒回终点；直接从停车位规划下一换行，A 8/8 完成。

三组最终异常验收均为实际 footprint 零碰撞、Hybrid 路径零碰撞、曲率零违规、非零速
换挡零次。当前入口逻辑同时包含清扫前硬交接门、旧固定路径偏离门，以及 action 已启动
后的早期清扫兜底门；精确时序与全部转场形状见异常报告。

当前架构契约见 [CURRENT_ARCHITECTURE.md](CURRENT_ARCHITECTURE.md)，完整异常时序和逐转场

## 未覆盖范围

本次结论只针对静态地图、真值定位和无动态障碍的导航算法。没有验证激光观测时延、动态
避障、定位漂移、轮胎侧滑、实际制动/转向延迟、CAN 看门狗或实车安全链，因此不能把仿真
通过等同于实机验收。“1 Hz 全局实时重规划且不拆 cusp”版本没有通过多区域全覆盖终态
验收；通过的是分层滚动规划、显式 cusp 和硬档位执行版本。
