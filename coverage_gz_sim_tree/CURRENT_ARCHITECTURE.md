# 当前全覆盖导航架构（隔离仿真树，更新于 2026-09-04）

## 结论

当前架构不预先计算任务级可执行全局轨迹，并把“进入首条清扫线”和“同一区域内换行”
明确分开：

```text
区域多边形
  -> 几何分解选择清扫方向
  -> 首入口静态可达距离门 + 无路径时间 beam 联合排列/定向清扫线
  -> 首条线入场：Navfn 全局路径 -> TEB（单个普通导航 action）
  -> 清扫：TEB 跟踪有向直线，禁止倒车
  -> 下一条已选清扫线：实时位姿 -> 一次直接 Hybrid A* -> 按 cusp 拆分 -> TEB
  -> 入口 hand-off gate -> 下一条清扫线
```

- 首条清扫线入场直接使用 Navfn + TEB，不再把 Navfn 拓扑转换成滚动 Hybrid A* 块。
- 同一区域内换行不再被强制限定为物理相邻线，也不使用 Navfn。从清扫线实际停车位到
  排序器选定的下一入口只规划当前这一条短连接，使用直接 Hybrid A*。
- 一条 Hybrid 连接由管理器按 cusp 拆成固定档位 action；每段由 TEB 闭环跟踪，换挡前
  强制零速。TEB 的 `motion_direction_mode` 硬约束该 action 的速度符号。
- cusp 停车后不是固定重规划。管理器先用实测位姿检查能否以同档、切向且满足 1.35 m
  半径约束接回下一缓存段；能接则裁掉旧 cusp 锚点继续，不能接才重算到原最终入口的完整
  剩余路径。
- 默认只在新转场、路径偏离、阻塞或入口异常时搜索 Hybrid。1 Hz 周期可以检查路径，
  但不会无条件替换仍有效的路径。
- 清扫入口不满足位置/横向/航向合同就保持 `TRANSITING`，不会先进入 `SWEEPING`。
  异常修正仍使用倒车代价较低、总长受限的 Hybrid 恢复；本仿真树已移除固定 1.20 m
  累计前进距离拒绝门，生产工作区尚未同步这一实验改动。

本文仍保存隔离仿真的参数和判断口径。通过该仿真收敛的架构后来已经适配到权威工作区，
生产控制链与发布状态以
[`docs/COVERAGE_NAVIGATION_ARCHITECTURE_20260903.md`](../docs/COVERAGE_NAVIGATION_ARCHITECTURE_20260903.md)
为准；本文的运动数据没有因此变成实车验收。

## 各阶段的规划与控制权威

| 阶段 | 全局路径权威 | 实际速度权威 | 说明 |
| --- | --- | --- | --- |
| 首线入场 | Navfn | TEB | 普通点到点；首次区域和切换后的新区域相同 |
| 线间转场 | 直接 Hybrid A* | TEB | 无 Navfn；按 cusp 拆固定档位 action |
| 直线清扫 | 覆盖管理器的 enforced path | TEB | 稠密有序 via-point，禁止倒车 |
| 入场异常恢复 | 受限 Hybrid A* | TEB | 倒车低代价、总长不超过 4.0 m；仿真树不再按累计前进距离拒绝 |

隔离仿真和生产源码现在使用同一控制职责：move_base/TEB 维持 action 生命周期、基于反馈
优化局部轨迹并生成唯一速度指令。`hybrid_teb_command_mux` 只在许可、TF、路径、TEB 指令、
固定档位和曲率合同均有效时把该指令转发到 `/cmd_vel_sim`；它不计算跟踪目标或速度，因而
不是第二个局部规划器。

### 清扫线顺序与首入口

隔离树已恢复确定性有界 time beam，并去掉直接 Hybrid 模式中“只能相邻蛇形、只能比较四种
首尾组合”的限制。beam 宽度为 128，同时选择第一条线、后续线序和每条线方向。它仍不
生成任务级 Hybrid 轨迹：首入口只查询静态已知自由空间距离，后续边只用 1.35 m 曲率约束
下的前进/倒车 Dubins 秒级代理，实际连接仍在执行前从实时位姿调用 Hybrid A*。

首入口与后续换行采用两级目标，避免完整路线的少量收益把首目标推到远端：

1. 先只保留静态已知自由路径长度不超过最短值 `+0.30 m` 的端点；
2. 再只保留预计 Navfn 入场时间不超过最短值 `+1.0 s` 的端点；
3. 最后在这些候选中最小化整区预计时间，后续线允许跨过物理邻线。

`0.30 m` 是排序候选带，不是 Hybrid 最终目标容差或清扫 hand-off 容差。当前权威工作区和
J6M release 仍使用固定相邻蛇形排序；本段是尚未同步的隔离仿真改动。

TEB 前视限制每次局部优化纳入的全局参考路径长度；当前架构不存在另一套自定义跟踪器前视。

## 线间转场生命周期

1. 上一条清扫线按有向终点和实测零速完成，不要求倒回精确终点。
2. 用实时 `map -> base_link` 位姿和下一条线入口调用一次直接 Hybrid A*；不经过 Navfn，
   不使用任务开始时缓存的连接轨迹。
3. 完整带符号路径按 cusp 拆成固定档位 action。TEB 在 action 末端减速；位置/航向、短段
   有向进度和 `/odom` 零速全部满足后，管理器才验收该段。
4. 到达 cusp 后先在旧后缀前 0.30 m 内找满足档位、切向和 1.35 m 半径的连接点。找到就
   把实测位姿作为新起点继续；找不到才丢弃旧后缀，并从当前实测位姿直接规划到最终入口。
   因此“到 cusp”不是异常，也不等于“必定重新搜索”。
5. 管理器持续观察相对当前 Hybrid 局部切向的航向误差和横向偏差，并使用
   `2.0 s / 0.10 m` 无进展门。连续超差或无进展时精确取消当前 generation 的 action，
   从实时位姿重算；当前重算仍失败时退避 2.0 s 后重试，最多 3 次。
6. 一旦进入下一条线的 `0.40 m / 0.40 m / 0.436332 rad（25°）` 位置/横向/航向
   hand-off basin，
   管理器立即取消当前 action 使 TEB 减速，不再追赶内层采样终点；实测停车后直接验收入场。

## 首线入场与异常恢复

正常首线入场现在始终是一个 Navfn + TEB action。它属于普通点到点导航，不计入线间
转场耗时。D 区从区域中央到首线的测试暴露出 TEB 在短距离调姿时出现速度符号抖动，
这是已记录但按当前要求暂缓处理的问题。

首线入场不再把 `max_global_plan_lookahead_dist` 覆盖成 Hybrid 的 2.0 m，而是保留普通
Navfn + TEB 的 4.0 m基线。Hybrid 区内转场仍单独使用 2.0 m，不受此修改影响。

如果正常入场 action 结束后仍不满足清扫入口合同，清扫不会启动。异常恢复沿用此前验证
的 Hybrid 逻辑：规划代价按前进 0.20 m/s、倒车 0.80 m/s 计，换挡代价 0.15 s；候选
总长不得超过 4.0 m。固定的 1.20 m 累计前进距离门已从本仿真树的源码和配置中删除；
Hybrid 碰撞、未知区、1.35 m 最小曲率半径和 `0.30 m / 20°` 目标区域仍有效，外层还要
通过实测 `0.40 m / 25°` hand-off。规划失败不跳过清扫线，而是有限重试后暂停。

## 当前 TEB 仿真结论

最终入口搜索区域已从 `0.15 m / 0.20 rad` 放宽为 `0.30 m / 20°`，外层入场验收同步
放宽为 `0.40 m / 25°`，但中间 cusp 仍保持 `0.25 m / 0.20 rad`。25° 比 20° 多出的
5°用于吸收 TEB 跟踪误差；曾试验 30° 外层航向门，但它会把约 28.5° 的姿态直接交给
禁止倒车的清扫段并导致停车，因此没有采用。

排序修改前的固定相邻基线在 A 区连续 3 轮完成 9 次线间转场，时长为
12.996--14.506 s，平均 13.781 s；每轮实际换向均为 6 次，零碰撞、曲率违规、非零速
换挡、无进展和振荡。
转场累计停车 2.704--4.134 s，TEB 局部路径相对当前 Hybrid 全局参考的 P95 最大偏差为
0.034--0.043 m。耗时主要仍是 cusp 停车和事件搜索，不是 TEB 卡死；10 s 现在保留为
性能告警值。

另在第二条清扫线入场前注入 0.220 m 横移和 10.31° 偏航。注入后实测横偏 0.235 m、
航向误差 12.44°，管理器没有启动 Hybrid 恢复或前进绕圈，0.238 s 后直接开始原清扫线；
任务 `COMPLETED`，仍只有 6 次实际换向。

恢复 time beam 后，A 区受控同初值回归选择物理线序 `[0,3,1,2]`，不再固定
`[0,1,2,3]`。三次转场为 7.500 / 11.504 / 13.502 s，总计 32.506 s，较上述相邻基线的
平均每轮 41.343 s 降低 21.4%；事件重规划由每轮 6--7 次降为 3 次，停车累计由约
10.0 s 降为 5.728 s。长条区域的首入口距离门回归也选择最近端点并直接进入首线，整区
完成；详细证据与仍存在的 Navfn 入场异常见
[ROUTE_SELECTION_VALIDATION_20260904.md](ROUTE_SELECTION_VALIDATION_20260904.md)。

较早的 0.35 m 横向、0.25 rad 航向入口扰动不满足当时更严格的外层入场容差，恢复规划为
倒车左弧 0.60 m 再前进右弧 0.90 m，计划 1.50 m，5.36 s 后重新启动原清扫线。0.55 m/s
冲线最终超出 0.623 m，系统
在停车前没有完成清扫，随后从实际停车位开始下一转场。详细数据见
[TEB_FIXED_GEAR_VALIDATION_20260904.md](TEB_FIXED_GEAR_VALIDATION_20260904.md)。

## 当前 1 Hz 对照结论

`direct_1hz.launch` 只把 `hybrid_replan_every_cycle` 从 `false` 改为 `true`。当前 TEB 对照
`teb_fixed_gear_compare_1hz_v1_20260904_001514` 在首个固定前进段产生 6 次周期搜索；每次
替换都伴随 mux 归零窗口，3 s 内仅前进 0.092 m，随后触发无进展取消。恢复候选总长
4.50 m，超过 4.00 m 入口恢复硬边界，任务于 43.00 s 进入 `PAUSED`，未完成首个转场。
事件版完成 A 区且没有 1 Hz 搜索。因此无条件 1 Hz 不是当前默认架构；保留该 launch 仅作
对照，不能用于生产。

## 验证边界

历史重复试验共覆盖 A、C、自定义 D 三个区域的 39 次线间转场，使用的是已经删除的自定义
跟踪器，不能作为当前 TEB 架构证据；逐次数据仅作对照，见
[TRANSITION_EXPERIMENT_REPORT_20260903.md](TRANSITION_EXPERIMENT_REPORT_20260903.md)。
异常入口和冲线历史试验见
[FAULT_INJECTION_EXPERIMENT_REPORT.md](FAULT_INJECTION_EXPERIMENT_REPORT.md)。

仿真不包含激光、动态障碍、定位噪声、轮胎侧滑、真实转向/制动迟滞、CAN 和运动安全链，
所以这些结果不是实车验收。
