## 本轮修改

- 候选 `autolabor_operator_gui` 的 `main_window.cpp`、`main_window.h`：新增被动预览页，
  图像订阅仅在该页可见且窗口未最小化时建立；只缓存一帧，仅新帧或尺寸变化时缩放。
- `operator_gui.launch`：新增默认 false 的 `initial_bpu_preview`，正常启动页和 RViz
  默认配置不变；Qt 契约测试增加两项。修改前四个文件保存在本实验 `qt_before/`。
- `tools/qt_bpu_bridge.py`：无窗口、无相机所有权的显示桥接，复用已有 ZED topic，
  只发布 `/fod/bpu_preview/image` 和 `/fod/bpu_preview/status`（另有 ROS 自身日志）。
  源帧身份、尺寸、时间、检测数值和 display-only 标记均校验；异常时只停止实验桥。
- 桥接每两秒至多一帧、最多一帧在途，队列长度 1；Qt 无订阅时取消相机订阅，并以
  EOF 关闭该会话的 J6M worker。BLAS/OpenCV 单线程，两端 nice=10。
- 增加相机 + Qt 独立静止测试入口、导航伴随桥接入口及验证脚本。会话最长 600 秒，
  不安装服务、不自动重启、不启用导航；退出只处理本次创建的进程。
- `bpu_preview_worker.py` 增加磁盘余量检查；与既有导航 master 并行需要显式
  `--display-with-navigation`，不能据此放开运动或改变控制链。
- 修正旧独立 OpenCV 预览每第十帧期间重复写截图的问题，改为同一结果只写一次。

此前独立预览还部署了私有 NumPy 1.26.4 到 J6M 本实验 `vendor/python311`；
没有修改全局 Python、HBRT、BPU 驱动或系统服务。ZED SDK/图像处理仍在 NVIDIA。

## 启动、停止与恢复

所有命令在 NVIDIA 执行。当前仅允许第一种静止显示入口；完整导航仍受
`STATIONARY_FOLLOWUP_20260905.md` 的安全暂停约束。

```bash
cd /home/slam/robot_j6m_ws_optimized_20260905
# 仅相机 + Qt + BPU，不启动底盘/导航，默认三分钟，最长十分钟。
bash experiments/j6m_bpu_20260905/tools/start_qt_preview.sh --seconds 180

# 从另一个终端提前结束；也可关闭本轮 Qt 窗口。
bash experiments/j6m_bpu_20260905/tools/start_qt_preview.sh --stop
```

前台启动终端需保持打开。脚本自动进入只读根隔离环境，原版/候选导航正在运行时拒绝
抢占相机；日志写本实验及候选 `log/ros`。显示测试关闭深度只作用于独立 launch，
**正式 ZED launch 的深度、避障、急停和失联停车没有改动**。

未来完整候选导航获准恢复并通过启动检查后，可在已有导航旁运行：

```bash
bash experiments/j6m_bpu_20260905/tools/start_qt_bridge.sh --seconds 600
```

它先检查 ROS master 属于候选版，再复用 `/fod_camera/image_raw`，不再打开一台相机；
在导航 Qt 选“BPU 预览”页即可显示。Ctrl-C 只停止桥接；离开该页只暂停预览。
**这一伴随完整导航的资源争抢及恢复场景尚未实机验证，不是现在重启导航的指令。**
原 YOLO 如果还选为正式后端，仍会继续运行；这个可选预览不自动关闭它。
