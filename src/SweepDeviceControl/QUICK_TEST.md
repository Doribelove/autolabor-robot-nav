# 清扫装置快速验证

程序：`/home/slam/robot_ws_agx/scripts/sweep_test.py`。
直接使用 Python 3 标准库和本目录原 `SweepDeviceControl.py` 中的协议定义，
不需要 ROS、额外安装包或重新编译，可与当前导航同时运行。

## 交互测试

```bash
cd /home/slam/robot_ws_agx
./scripts/sweep_test.py --ip 192.168.0.197
```

连接后先显示清扫装置当前状态，再输入以下字符并回车：

| 输入 | 操作 |
| --- | --- |
| `1` | 启动清扫装置，并查询确认开启 |
| `0` | 停止清扫装置，并查询确认关闭 |
| `s` | 只查询当前状态 |
| `e` | 液压杆升出，默认 2 秒 |
| `r` | 液压杆回收，默认 2 秒 |
| `q` | 停止并退出 |

菜单中的 `Ctrl+C` / `Ctrl+D` 也会尝试停止并退出；如果设备通信已断开，程序会
报告无法确认关闭，不会把断开 TCP 连接当成装置已关闭。

## 单条命令

```bash
./scripts/sweep_test.py status --ip 192.168.0.197
./scripts/sweep_test.py on     --ip 192.168.0.197
./scripts/sweep_test.py off    --ip 192.168.0.197
./scripts/sweep_test.py extend  --duration 2
./scripts/sweep_test.py retract --duration 2
```

`on` / `off` 在设备回报目标状态后退出，保持对应开关状态；`on` 命令退出后装置
继续开启，需要 `off` 关闭。返回码 0 表示收到确认状态，2 表示连接/状态确认失败，
130 表示命令被中断。

设备默认 TCP 端口为 `50003`，可用 `--port` 指定。`--timeout 2` 为单次通信超时，
`--settle 4` 为切换后轮询目标状态的等待窗口。

## 液压杆升降（2026-10-13）

已根据桌面新版 `SweepDeviceControl.py` 加入液压杆协议与函数。
在 Qt 的“清扫 → 液压杆升降”中点击“液压杆升出”或“液压杆回收”。
单次动作默认 **2 秒**，时长选择仅提供设备支持的 2 秒、3 秒；不接受其他时长。
命令行 `extend` / `retract` 省略 `--duration` 时同样使用 2 秒。

液压杆的两个方向沿用研究所 demo 的命名，未推断安装机构的升高/降低对应关系。
控制器只返回命令接收应答，不回传位置或到位信号，因此界面显示“指令已接收、
动作计时结束”，不将其当作已到位。升降结果独立显示，保留原清扫启停状态。
手动清扫启停仍是独立操作；相机自动回收改为固定 3 秒联动，不受手动时长选择影响：

- `./scripts/sweep_test.py recovery-start --json`：升出液压杆 3 秒，收到 ACK 后立即启动清扫。
- `./scripts/sweep_test.py recovery-stop --json`：停止清扫并紧接着回收液压杆 3 秒。

两项命令在同一 TCP 连接内连续发出，液压计时和清扫启停重叠执行；完成状态查询及
3 秒计时后释放设备锁。自动回收每轮只升出一次，GPS 到达、视觉完成、取消或中止
统一停止清扫并回收一次；原本已手动开启的电机也会在本轮结束时停止。
联动 JSON 另返回 `hydraulic_sent`，清扫状态由实际回读给出；液压仍只有 ACK，无到位反馈。

Qt/命令行通过同一设备锁串行执行，单次升降期间等待动作时长再释放。
每次点击只发送一次液压杆帧；应答丢失或断线时显示“未确认”，不自动重发。
升降期间点击“停止清扫”会在当前请求结束后停止清扫电机；该按钮不是液压杆急停。
原协议没有提供液压杆停止命令，液压动作由控制器按 2 秒或 3 秒计时执行。

`extend --json` / `retract --json` 除原字段外返回 `duration_s`、`acknowledged`、
`position_confirmed=false`；此处 `success` 只表示已收到命令应答并结束等待，
`state=-1` 不代表清扫器关闭，也不能用来推断杆位置。

## 协议与地址

随附说明书和原程序的主函数使用 **192.168.0.197:50003**，因此验证程序默认
采用此地址；原类构造函数另写了 `192.168.1.197`。实际设备地址如已改动，使用
`--ip 实际地址`，程序不会自动切换到另一个设备。

设备是单 TCP 连接服务器。测试时应退出其他清扫控制客户端，否则可能无法连接。
Qt 的“清扫”页现已接入同一验证程序，提供“启动清扫”“停止清扫”“查询状态”
以及 IP/端口设置。打开页面时每 5 秒查询一次，操作期间只保留一个 TCP 连接；
关闭页面停止轮询。顶栏显示最近一次回读的清扫状态。

启动/查询进行中点击停止，会在当前请求结束后执行停止；不会并发发送切换命令。
Qt 关闭不会自动切换清扫器，离开前需要点击“停止清扫”并确认“已关闭”。
CLI 的交互菜单 `q` 则仍会尝试停止设备后退出。
不要在 Qt 清扫页轮询时同时运行独立测试客户端。

程序接口 `./scripts/sweep_test.py status --json`（也支持 `on`/`off`）在标准输出
返回 `action/success/state/message`，通信日志写标准错误；Qt 异步读取结果，不阻塞界面。

原协议只有一条开/关切换命令，没有独立开机或关机帧。因此程序：

1. 先查询当前状态；已经是目标状态时直接返回。
2. 只在当前状态相反时发送一次切换。
3. 查询实际状态确认；丢失 ACK 时也只重试查询，不重复切换。

收到 `OK!` 只表示命令应答，只有状态帧回报目标状态才显示成功。初始状态未知时
不能推断切换后是开还是关，因此返回具体错误。原启停帧保持不变；
`SweepDeviceControl.py` 已补入新版 demo 的液压杆帧和函数。
