二、已经实测：官方六相机模型基线

只将开发包七个 ARM64 运行库复制到板端私有目录：
  /tmp/conbine-oe391-YSqnpbu5/lib
各文件上传前后 SHA 一致；通过进程 LD_LIBRARY_PATH 使用，不覆盖系统库或正式 current。
实际 UCP 3.15.8、DNN 3.15.8_(4.11.11 HBRT)。底层 BPU 驱动等仍使用板上已有版本。

hrt_model_exec 复用既有可执行文件，并非新编译的 OE 工具：
  /map/robot_j6m_navigation_20260907/bpu_lab_20260905/vendor/runtime_4_9_2/bin/hrt_model_exec
  SHA256 1e21a3e715c14a249c5ea127cbea6f60dbf4aef8428f10fcd91f2a949d6085ef
本轮 loader.log 和 model_info.log 证明其实际装载的是新 DNN/UCP/HBRT 库。
模型名 bev_vtv2_resnet50_nuscenes；14 输入（六对 NV12 + 两个 S16 采样网格），
6 个 S32 SCALE 输出（通道 2/1/3/2/2/10），仍为 nuScenes 六相机交通模型。

正式复测：中性 NV12 + 零采样网格，单核、单线程、100 次：
  模型调用均值            16.41243 ms
  profiler BPU 推理均值   16.36031 ms
  BPU core process 均值   16.25170 ms
  profiler CPU 推理       0 ms；一个 BPU 子图
  工具报告吞吐           60.74755 FPS
CPU 仍负责输入/内存/提交等工作。没有逐层编译报告，不拆分编码器/融合/检测头时延。
这不是四路垃圾检测准确率，也不是图像采集到地图点发布的端到端延迟。

常驻适配器：首次旧可执行文件因写死 3.14.5 版本而拒绝新库，失败证据保留。

  export BEV_OE_SDK="$PWD/runtime/oe391_20261101/horizon_j6_open_explorer_v3.9.1-py310_20260821"
  python3 tools/bev_feature/prepare_official.py --compiler-artifacts
  python3 tools/bev_feature/oe391_environment.py package --sdk "$BEV_OE_SDK" --output validation/oe391_package_repeat.json
