实现
1. J6M 一个常驻 FCOS 模型依次识别 front/left/right/rear 四路原图。
   等比例缩放至896内，左上对齐、黑色补边、BGR->I420->NV12，保持图像比例。
   两个U8输入为Y [1,896,896,1]、UV [1,448,448,2]；15个S32量化输出反量化。
   80类COCO保留原类别。score=sigmoid(class)*sigmoid(centerness)，阈值0.20，
   LTRB*stride，类内NMS IoU0.6；按实际取整后的XY缩放分别还原原图框。
   复用原实验 decoder；与授权 HEAL 精确前后处理数值等价性仍未独立核验。
2. BPU执行FCOS网络：旧适配器hbDNNInferV2创建任务，hbUCPSubmitTask指定BPU_CORE_0。
   J6M CPU负责JPEG解码/NV12准备/输出反量化/NMS，Jetson CPU负责传输/几何/绘图/Qt。
   本次不是将几何BEV或学习式BEV特征融合放到BPU，不能称四视角特征联合网络。
3. 检测框底部中点按各相机K和外参投到地面Z=0，得到rig平面米制x/y；不是深度，
   不是实测物体占地中心。跨相机15cm内且双方原图框互投影匹配时合并，同相机不合并。
   FCOS要求类别一致；旧材料专用检测器仍支持材质标签冲突合并。
4. /frame与/detections新增scene_ground_objects供显示所有可投影物体。
   兼容原清扫接口ground_objects：FCOS仅bottle/cup进入清扫候选，不把人/家具等标为垃圾。
   这是类别选择，不能证明瓶杯确为废弃物。Qt显示全体目标及候选数量，不自动启动清扫。
   未更改普通导航或运动控制；本次不发目标、速度、机构命令。
5. ZED SDK继续DEPTH_MODE::NONE，front_depth_enabled=false，未修改相机标定/拼接。
   平面IPM中的立体物体拉伸仍存在；识别使用原图，不用拉伸后的BEV图作模型输入。

边界
COCO80是通用物体检测，垃圾材质/脏污/小碎片识别仍需针对本车数据训练，不能仅靠换显示标签。
立体物体未触地、框底接触点不准确或图像边缘截断时，地面点可能有偏差；误判也可能形成点。
没有实物跨相机移动、车辆换位、独立实测地面真值，重复点/地图稳定性/二维米制误差尚未验收。
重装相机组到底盘平面偏移仍未重新确认，rig_to_base_xyyaw=[]；本次只显示rig坐标，
没有伪造base/map位置，未接通完整自主拾取，也没有启动真实导航。

可复制命令（工作目录/home/slam/robot_j6m_ws_conbine）
启动当前默认FCOS+BPU+Qt：
  bash scripts/camera_surround.sh start
查看实际模型/四路/帧率：
  bash scripts/camera_surround.sh status
  curl -fsS http://127.0.0.1:18884/state
  curl -fsS http://127.0.0.1:18884/detections
重开Qt与检测器（保留原相机采集/BEV拼接）：
  bash scripts/camera_surround.sh stop
  BEV_DETECTOR_BACKEND=fcos_bpu bash scripts/camera_surround.sh start
需要切回原best6或原单类trash HBM时，先stop再将上条backend换为cuda或bpu。
停止Qt/识别用camera_surround.sh stop；这条命令不关闭相机，沿用原生命周期。
两路推理后端不可同时抢同一个BPU锁；当前服务启动失败时看runtime/bev_qt/bpu.log。
不调用训练/量化命令：此次复用已有官方FCOS HBM，没有训练或编译新的垃圾模型。
