## 实际实现

1. Qt 清扫按钮继续调用独立 `/pending_litter_cleaner/start_cleaning`，协调器向与
   综合页相同的 `/move_base_simple/goal` 提交普通点导航请求，经过原导航桥执行。
   订阅者校验改为检查指定导航桥及观察者身份，允许 `/autolabor_operator_gui`
   和 `/rviz` 显示订阅；未知订阅者或缺少执行桥仍明确拒绝。不再要求总连接数为1。
2. 垃圾的 map 坐标作为本次任务目的地，默认以 1.5 m 为接近半径，最多查询8个
   朝向垃圾的候选位姿。读取现有导航的车体外廓及 padding，在新鲜全局代价地图
   （包括增量更新）中检查完整外廓相交栅格，拒绝未知、越界及碰撞位置，再调用
   普通 `/move_base/make_plan` 确认可达。规划总等待有界，不写导航参数。
3. 只有目标位于1–2 m内且在车头前方±35°，才允许跳过接近导航。近处侧后方或
   过近目标仍通过普通导航调整，不要求阿克曼车辆原地转向。导航本身继续使用
   原 Navfn/TEB/避障和到达容差；本模块不会把全局导航容差改成1–2 m。
4. 协调器观察导航桥实际发出的 action，以传输后的序号、完整目标位姿、来源节点
   和桥的已发 GoalID 关联本次请求。达到朝向合适的接近距离时可精确取消本次目标，
   或等待其成功；随后等待桥确认该目标已终止且不会在正常视觉交接后重发。
   只有连续新鲜的停车里程计通过后，才暂存目标并请求原 FOD 仲裁器接管。
5. 暂存接口新增 `completion_policy`、`request_id`。待清扫模块明确选择
   `visual_servo`：到近处后按新鲜 map 位置唯一重关联所选垃圾，允许导航期间检测
   ID 更新；多候选、位置不符或锁定后身份跳变仍拒绝。获取目标后沿用原像素跟踪、
   消失确认、车轮回正和滚刷通过流程，**不再要求额外的 map 10 cm 轨迹命中**。
   普通视觉默认的消失后0.50 m目标、0.55 m行程硬上限与全部安全门保持不变。
   完成证据使用该视觉会话实际配置的通过距离，不另强制改写视觉参数。
6. 只有原视觉控制器经过既有停车/传感器终态检查，生成本轮新序号、任务令牌、
   原列表 ID、实际获取 ID 和完成证据，并回到普通导航模式后，才删除对应列表项。
   任意手动切回 GPS_ACTIVE 不算清扫成功；失败/取消保留垃圾项目。
7. 清扫页改为中文阶段与常见拒绝说明，显示距垃圾距离，记录后台接近目标、GoalID、
   状态及拒绝原因。启动前发现其他任务会拒绝；运行中手动目标替换则退出自身任务，
   不取消新的手动目标。普通导航原有人工暂停/恢复语义没有改动。
