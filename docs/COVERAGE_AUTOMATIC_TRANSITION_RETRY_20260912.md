# 覆盖转场自动续试修改（2026-09-12）

## 目标

用户要求两类转场执行问题不再进入人工暂停：

1. Hybrid A*已经给出路径，但TEB连续无进展，有限重试次数耗尽；
2. 转场路径偏离或已经到达交接边界，取消旧动作后未在原3秒窗口内确认物理停车。

这次修改只改变上述执行故障的恢复方式。操作员主动暂停、任务取消、FOD安全仲裁、定位
丢失、避障感知失效和VCU/底盘故障仍会中断自动过程。

## 跟踪器的职责

覆盖管理器中的tracker是一组当前段内存字段，不是另一个ROS节点、规划器或控制器。转场
tracker记录沿Hybrid路径的有向进度、最大进度、路径偏离、终点边界和定位跳变；清扫tracker
记录是否从清扫入口开始、沿线最大进度、终点越界、横向和航向误差、停车样本及连续性。

它让管理器能区分“TEB接近目标点”和“机器人确实按正确方向走完覆盖段”，也让中断后的
清扫只重发剩余直线。2026-09-11 22:16的现场故障中，入口按0.40m横偏容差放行，但清扫
tracker要求0.30m才武装；当时约0.339m的横偏很可能让车辆开始清扫却没有建立连续入口
历史。TEB中止后，管理器因此不能安全续接。这一门限不一致不在本次修改范围，仍需另修。

## 修改后的行为

- `segment_retry_count`继续控制一轮内的有限尝试次数，但不再是Hybrid转场的人工暂停上限。
  一轮耗尽后保留同一段和它所依赖的清扫线，进入`WAITING_OBSTACLE`，按任务冻结的
  `transit_replan_period_sec`等待后开启下一轮，直到成功、安全暂停、任务取消或节点关闭。
- 清扫入口的rolling Hybrid对准使用相同的连续重试策略，不会因一轮对准次数耗尽要求点击
  恢复，也不会跳过该清扫线。
- 固定挡位路径偏离时仍先精确取消旧move_base Goal。若3秒内没有取得停车证据，管理器继续
  等待新鲜物理里程计；连续两个样本满足绝对线速度不超过0.08m/s后，才允许从实车位姿
  重规划。
- 已经越过转场边界或进入最终清扫入口但尚未停车时也使用相同等待。等待期间不提交新目标；
  停车确认后自动完成交接。
- 首次Navfn入场在有限重试后仍保留原人工暂停，因为它不属于用户指定的Hybrid线间转场。
