结果
实时采集路径固定 RX4/CIM -> PYM NV12 layer0 -> GDC -> 透视图 -> CPU YUV 转 BGR。
检测使用该透视图，YOLO11-GAM 和五材质分类仍由原双 HBM 在 BPU 执行。
实时预览复用 GDC 图像，BEV 只对透视图做地面投影/融合。
YUV 转 BGR、缓冲复制/SDK 调用、模型前后处理和 BEV 地面计算仍使用 CPU；
没有声称整条视觉链 CPU 零占用，也没有测得真实四路 GDC 吞吐或 CPU 降幅。

实现
capture.py：四路均要求 PYM/NV12/layer0、完整未裁剪的标定画幅、匹配的 GDC 输入/输出
尺寸和透视 LUT SHA256。启动前读取并固定实际验证过的 LUT 字节，随后每路加载一次。
缺参或错误配置在 SDK/相机打开前拒绝，主 run 入口在 BPU 初始化前完成上述检查。
每帧检查 GDC 完成标志、输出尺寸与实测格式，不接受未经 GDC 的实时图像。
GDC 失败仍沿原读取失败机制丢帧，连续 10 次失败停止该路；不回退 CPU 去畸变。
原生 capture.cpp 保留输入曝光计数器/序号/采集时刻，vendor_format 改为返回图像的
格式（启用 GDC 时使用 GDC 输出格式）；ABI 结构仍为 1。四路原生 GDC 继续串行。

geometry.py / pipeline.py：默认只接受已校正透视图。CPU 参考必须显式
offline_reference=True；仅 replay/参考测试启用。原始实时帧返回 awaiting_gdc，
不调用 CPU remap 或 BPU；有效实时结果标记 rectification_backend=gdc。
display.py：实时显示关闭 CPU 校正，未处理图像不叠加透视检测框或参与鸟瞰投影。
bev.py / bev_cli.py：camera 和 watch 强制透视输入，不生成 CPU 鱼眼查找表。
watch 外部生产者应输出 GDC 图像和匹配 rectification_id。images/demo 保留离线原图
输入能力；CPU 透视到地面 remap/融合未迁移。原始内参采图是独立 calibration-frames
入口，必须不配置 GDC bin，不做 CPU 去畸变，不进入实时推理链。
