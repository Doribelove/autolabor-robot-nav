采集和协议实测
HD720 1280×720，15 fps，QUALITY 深度，UNIT::METER，SDK IMAGE 坐标 x右/y下/z前；位置跟踪和深度稳定关闭。
发送的是与深度对齐的 SDK 左目校正彩色 BGRA8，保持完整采集分辨率；不是 Bayer/未经校正的传感器图，也不是有损编码。
AGX 不缩放、裁剪或归一化；原始 BGRA 与 32FC1 每平面各 3686400 字节，逐字节 LZ4 压缩和 CRC 校验。NaN/Inf 原样保留。
IMU 独立 CURRENT 采样，从约 400 Hz 原生唯一采样按时间网格选取 200 Hz；传原始 SDK 时间戳、序号、校准与未校准加速度/角速度、姿态及协方差，不插值、不重复盖时间戳。
IMU frame_id=zed2_imu_sdk_image_frame，明确为 SDK IMAGE 轴；原 ROS wrapper 选择 RIGHT_HANDED_Z_UP_X_FWD，不复用其 zed2_imu_link 名称冒充同一基底。后续 ROS 接入须同时转换向量、姿态、协方差与外参。
图像/深度 SDK 时间戳最大实测差 0 ms，20 ms 配对门保持；输出保留源相机序列号、session、sequence、时间戳和 optical frame。
相机内参、双目外参、SDK IMU→左目外参随帧传输；每次会话另有 current_calibration.json，防止相机重开后读取旧标定。证明帧的 metadata 单独保留。
车辆安装外参只记录历史来源，当前 T_base_from_left=null / 未复核，没有伪造单位变换用于车辆坐标融合。

IMU 时间问题、修正及未验收边界
初版将 SDK 原始 IMU 时间直接套入 -5..500 ms 年龄检查；较长运行出现 frame_age_out_of_bounds，触发断线与序号缺口。此时双机时钟对齐正常，已观察 SDK IMU 时刻略超前于主机参考时间；具体 SDK/设备时钟漂移来源未确认。final_delivery.json、sender_with_sdk_timestamp_rejections.json 与板端 revisions/before_imu_timing_separation/ 保留原失败。
修正保留 SDK stamp_ns；AGX 另外记录 SDK 读取调用的 host_read_begin_ns/end_ns。J6M 分开校验读取/传输新鲜度并记录 SDK 与主机时差，不替换原始采样时间，也不伪造校正后的时间戳。读取年龄须 -5..500 ms，读取调用不超过 100 ms，SDK/读取时刻差不超过 500 ms；旧时间/失去对时仍拒收。
原始 SDK 时间超出 -5..500 ms 时，原始数据可继续作为诊断数据传输，但 timing.fusion_time_valid=false；所有本候选 IMU 继续 source_clock_alignment_accepted=false、fusion_eligible=false、corrected_acquisition_stamp_ns=null。当前未实现或放行 IMU 融合。
六分钟快照中 SDK 时刻减 AGX 实际读取时刻约 -3.111..+4.013 ms；最终 v4 实测一条为 +3.080 ms，证实该差异可在 AGX 端直接观察，不能只靠双机 NTP 消除。完整 200 Hz 数据传输通过不等于 IMU/相机物理时刻对齐已验收。

故障与恢复
1. J6M 接收服务定点停止，由 AGX supervisor 恢复：7.767 秒内取得新接收 PID、同一源 session 的新鲜图像及 IMU，通过。
2. AGX 相机采集服务定点重启：6.036 秒内新 source session 恢复，板端随后确认新 session 和当前数据，通过。
3. 停止 AGX 私有对时服务约 10 秒：板端进入 waiting_for_fresh_data，末 3 次检查接收数不增长、旧检测源时间戳不变化；恢复对时后继续接收，通过。
   结果：rejects_during_clock_loss=True，recovers=True。
