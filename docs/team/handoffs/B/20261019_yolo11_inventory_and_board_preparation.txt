五、仍缺少什么、后续迁移顺序

1. 配套 x86_64 OpenExplorer CPU 工具链：horizon-tc-ui、hbdk4、hb_compile，
   固定镜像 digest / 包版本，与现有 DNN 3.14.5 和 HBRT 4.9.2 核对兼容性。
   当前没有可用的转换主机连接信息，也未确认配套 SDK 包路径；已向用户询问。
   不能把 x86 镜像直接装到 ARM64 J6M/AGX 当作原生可运行工具链。
2. 在转换机复用完整 private_ptq，检查并编译两份正式 HBM。
   检测含 GAM，ONNX 有 MatMul/Softmax 等算子；分类也含注意力相关算子。
   是否全部在 BPU、是否存在 CPU 回退及其代价，必须看实际编译分配和板端结果。
3. 对齐 FP32/量化/实板数值，核验分类顺序、前后处理和独立数据集精度。
4. 实现同一服务常驻两模型、统一独占锁与调度、会话/源帧身份和过期结果丢弃，
   接回 autolabor_fod_vision 的跟踪、深度配对、材质投票与原发布语义。
5. 实测 0/1/4/8 crop 整帧速度、P50/P95/P99 和断连/超时/重连等异常处理。
   本次没有准确率、帧率或全 BPU 覆盖率结果。

不需要为本轮搬运 AGX 的 CUDA、TensorRT、整个 PyTorch 环境或重装 BPU 驱动。
