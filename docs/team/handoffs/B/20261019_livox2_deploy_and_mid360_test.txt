四、网络修复与雷达身份

原问题：J6M 只有 eth0=192.168.10.100/24，没有 192.168.1.0/24 直连地址；
已有雷达配置的接收地址却是 192.168.1.100。仅复制驱动不能解决这项不匹配。

先用 ARP 探测确认 eth0、eth1 都能收到同一 MID360 的应答：
  MID360 IP：192.168.1.112；MAC：58:b8:58:79:18:dd。
  驱动检测到的设备 SN：47MDMBB0030112。
没有根据端口名称猜测线束；外壳端口与 Linux 网口的长期映射仍需现场登记。
测试选择已有 carrier、无 IPv4 地址的 eth1，MAC de:34:33:b5:2e:d3。
对 192.168.1.100 执行重复地址探测未收到应答后，仅给 eth1 临时添加：
  192.168.1.100/24
原 eth0 SSH 地址和默认路由不变，没有在两个网口重复配置同一个 /24。

临时地址生效后，路由实测为：
  192.168.1.112 dev eth1 src 192.168.1.100
J6M 直接 ping 3/3 成功，0% 丢包，独立连通阶段 RTT 平均约 1.85 ms。
正式接收测试前再次 ping 成功并核对 eth1 邻居 MAC 为上述 MID360。
没有开启 AGX 转发，雷达数据由 J6M 直接接收。

本轮 mid360.json 从本副本 AGX 配置生成，四项 host 接收 IP 改为 192.168.1.100；
雷达 IP 保持 192.168.1.112，主机接收端口保持 56101/56201/56301/56401。
原 AGX 配置和 J6M 旧配置均未覆盖。SDK 启动按该配置设置接收参数和正常工作模式；
不声称雷达内部运行参数已恢复到测试前，也没有修改雷达固件或静态 IP。
