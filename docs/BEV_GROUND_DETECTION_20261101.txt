当前交付
用户最新要求以可用的 BEV、垃圾识别和二维定位为目标，BPU 可以加速。
已将当前预览/清扫观测入口改为：四路翻正原图识别 -> 按每路内外参投影
地面接触点 -> 跨相机重叠观测合并 -> BEV 米制网格与坐标标记。
这条路径使用现有模型，无需先安装 Windows/WSL、获取 HEAL 或重新编译 HBM。
既有四路特征融合原型与官方六路基线保留；当前入口是观测点融合，不能称为
学习式四路 BEV 特征融合模型。背景仍使用地面平面投影，墙、箱等立体物体仍会
拉伸；本次主要消除了在拉伸的 BEV 图上做垃圾检测这一识别误差来源。

原图输入固定 front/left/right/rear，来自同一次 BEV compose 快照，新增 /views
打包原图与其 BEV/标定/源帧标识。没有重新打开相机。采集快照一致不等于曝光同步。
沿用当前 config/four_camera_bev.json：X 向前、Y 向左，左右中点地面投影为原点；
BEV x=[-2,4]m、y=[-3,3]m、每像素0.01m。栅格分辨率不代表定位精度。
定位用识别框下缘中心（有有效分割接触点时使用该点）的光线与地面相交。
输出是地面接触点估计，不是真实垃圾占地轮廓的中心。截断接触点、朝天光线、
车体遮挡和范围外点不发布为有效地面观测。不同相机同标签点相距不超过0.15m时
做完整组内距离约束的合并，同相机两个目标不会在本步骤合并；该阈值尚未实车整定。
置信度取组内最大值，不伪造融合后的概率提升。

入口与复现命令（项目根目录执行）
配置检查：
  bash scripts/camera_surround.sh check
打开四路、BEV 和 Qt，使用默认 CUDA：
  bash scripts/camera_surround.sh start
使用已验证的旧垃圾 HBM：
  BEV_DETECTOR_BACKEND=bpu bash scripts/camera_surround.sh start
上述 start 不启动真实导航；已有会话运行时不会热切换后端。需切换时先 stop，
再按所需后端 start。完整结束 Qt、BEV 与四路采集：
  bash scripts/camera_surround.sh stop
  bash scripts/camera_bev.sh stop
  bash scripts/four_camera_view.sh stop
如果四格启动前旧 ZED sender 正在运行，四格退出会恢复该旧服务，和原生命周期一致。

运行中查看状态及地面点：
  curl -s http://127.0.0.1:18884/state
  curl -s http://127.0.0.1:18884/detections
后者保持 conbine.bev.cleaning.observations.v1，ground_objects 含 x/y（米）、
confidence、label、source_cameras、position_method、frame_id。
Qt 继续使用原 BV01 协议，显示实际 CUDA/BPU、BEV 点位和二维坐标；点位周围的小框
仅为显示标记，不是由 BEV 图检测出的包围框。旧 Qt 垃圾地图页面没有恢复。

实际验证
证据根目录 validation/bev_ground_detection_20261101/。
1. 原图投影/越界过滤/交界合并/近邻保持/原子图像协议等20项检查通过，
   geometry_tests_final.log。Qt Release 构建成功，8项解码检查通过，qt_tests.log；
   包括读取真实 BPU 回放服务生成的 BV01 报文。不是只检查模拟后端字符串。
2. J6M 实际运行四路原图垃圾 HBM；每路 vendor_infer 约6ms，四路约24.5ms。
   含 JPEG 编码、传输、解码、预处理、拷贝、解码框的四路调用中位145.83ms。
   默认 CUDA 四路调用中位113.69ms。各为5次调用、去除第1次后统计；本轮两个
   后端部分诊断并行运行，不是受控性能对比，且权重/输入尺寸不同。
   因此 BPU 内核快不等于当前跨主机完整流程快于 CUDA；默认暂保留当前模型。
3. BPU HTTP 回放贯通 original views -> geometry -> BEV frame/detections，
   http_preview_fixed/result.json 通过，一次四路调用174.64ms。
   实拍四路回放场景中两后端均没有>=0.25的垃圾框，不能用这组空结果验收定位精度。
4. 从旧 image_label/images/test 确定性抽20张有框图片，共38个标注；统一缩放
   最长边1280，按单类垃圾IoU>=0.5匹配。BPU：20预测/19匹配，P=0.95、R=0.50；
   CUDA640：26预测/20匹配，P=0.769、R=0.526。样本少、与训练集是否重叠未知，
   不是本车实际精度，召回结果也不足以承诺清扫时不漏检。报告分别在
   bpu_resized/report.json、cuda_resized/report.json。
5. 额外尝试CUDA1024，四路中位178.81ms，旧标注17/38匹配；未体现提升，保持640。
   cuda1024/report.json。首次OpenCV整数参数与诊断大图JPEG大小问题已修正，
   初次失败证据保留，最终几何/协议与HTTP/Qt检查使用修正后的文件。
