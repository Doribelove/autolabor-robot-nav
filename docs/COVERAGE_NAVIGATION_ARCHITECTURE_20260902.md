# 全覆盖导航当前架构（2026-09-02）

> 历史版本：本文记录 release `20260902_204607` 的滚动 Hybrid/cusp 分段架构，不能用于
> 判断 2026-09-03 之后的当前实现。当前架构见
> [COVERAGE_NAVIGATION_ARCHITECTURE_20260903.md](COVERAGE_NAVIGATION_ARCHITECTURE_20260903.md)。

## 当前结论

正式工作空间现在采用分层、按需规划架构：

```text
区域多边形
  -> 几何选择清扫角度
  -> Dubins 秒级代理联合决定清扫线顺序和方向（不生成连接路径）
  -> coverage_manager 持有唯一 plan_id、当前清扫线和 action generation
  -> 每个实际转场从实时 map -> base_link 位姿开始
  -> Navfn 只提供长距离已知自由空间拓扑
  -> 约 10 m 滚动目标
  -> Hybrid A* 生成当前运动学前缀
  -> 按每个 cusp 拆成固定档位 move_base action
  -> 零速换档门
  -> 清扫线入口硬交接门
  -> 前进-only 精确清扫线
```

它不再为整项任务预计算并缓存可执行 Hybrid 全局轨迹，也不采用“每 1 Hz 从实时位姿到
最终入口完整重算且不拆 cusp”的简化方案。任务启动前只保存区域、清扫线顺序/方向和逻辑
入口；当前前缀完成、阻断、无进展、连续路径偏离或入口超差时，才从实时位姿规划下一段。
move_base 仍保留 1 Hz 全局规划周期，但
`CoverageGlobalPlanner/hybrid_replan_every_cycle=false`，一个已经交接的单档前缀不会仅因
定时器触发而无条件换拓扑。

本架构已部署到 J6M release `20260902_204607`。部署只更新 install-space 并保持主链停止，
没有发送初始位姿、导航目标或非零速度。

## 车辆与统一运动学

- 轴距：`0.65 m`。
- VCU 最大前轮转角：约 `0.488692 rad / 28°`。
- 覆盖管理器、Hybrid A*、CoverageGlobalPlanner 和 TEB 的最小转弯半径统一为
  `1.35 m`；对应所需前轮转角约 `25.71°`，相对机械上限保留约 `2.29°` 裕量。
- Hybrid 状态分辨率 `0.15 m`、72 个航向格、5 个转向采样，运动步长
  `0.30 m`，完整 footprint 碰撞采样间距 `0.10 m`。
- 导航 footprint 延续项目正式配置；未知格、致命格和地图外均不可通行。
- TEB 的转弯半径边是软优化约束，因此输出端另加
  `|omega| <= |v| / 1.35` 硬投影；零线速度时不允许残余原地角速度。

启动覆盖任务前仍会在线核对 VCU 轴距/转角、TEB 和 Hybrid 参数，不一致时 fail-closed。

## 任务层排序

清扫角度仍按几何完整度选择。选定清扫线后，任务层用障碍无关的 Dubins 最短曲率长度、
前进/倒车速度、加速度、角速度以及换档/停车时间构成秒级代理，在有限 beam search 内联合
选择清扫线顺序与方向。这个阶段：

- 不调用栅格 A*；
- 不调用 Hybrid A*；
- 不生成任何可执行连接轨迹；
- 不把 TEB 的多量纲优化 cost 当作秒数。

这一步主要避免相邻清扫线被定成同向，从而产生 13–17 m、接近 360° 的大前进圈。真实静态
连通拓扑和运动学可行性留到该转场即将执行时处理。

## 转场生命周期

1. 管理器从实时位姿向原清扫线入口请求滚动转场。
2. Navfn 在完整静态图上给出已知自由空间拓扑，沿该拓扑截取默认 `10.0 m` 目标。
3. Hybrid A* 只规划当前滚动目标；单次服务预算 `3.0 s`。
4. 返回路径按位姿切向恢复前进/倒车符号，并在每个 cusp 拆成单档 action。
5. 每个 action 完成后先精确取消/确认 terminal，再由新鲜 M2 `/odom` 连续确认线速度
   不大于 `0.08 m/s`，才允许换档。
6. 正向子段禁止倒车；反向子段允许低速倒车并以路径朝向、有序 via-point 和单一同伦类
   引导 TEB。任一 action 阻断、无进展或偏离后，不继承旧 cusp，而从实时位姿重算。

正式链仍由 move_base + TEB 输出到既有 FOD 仲裁、定位门和 NVIDIA 最终看门狗，不引入
仿真中的真值位姿命令复用器。固定档位路径连续 3 个样本横向偏离大于 `0.35 m`，或相对
局部路径航向偏离大于 `0.40 rad` 时，只取消本任务当前 generation 的 action；停车后重算。

## 清扫线入口恢复

清扫 action 发出前有独立硬门：距入口、横向误差、航向误差必须分别不大于
`0.30 m / 0.30 m / 0.40 rad`。任一超限，状态保持 `TRANSITING`，不会短暂进入
`SWEEPING`，而是用同一滚动 Hybrid/cusp 管线重新捕获原入口。

入口恢复的代价专门偏向短倒车修正，但不改变物理速度上限：

- 规划等效前进/倒车速度：`0.20 / 0.80 m/s`；
- 换档代价：`0.15 s`；
- Hybrid 内层目标区域：`0.15 m / 0.20 rad`；
- 实际清扫交接仍以原入口 `0.30 m / 0.40 rad` 为权威；
- 恢复候选总长不超过 `4.0 m`；
- 累计前进不超过 `1.20 m`。

超过长度边界的候选按“大幅前进绕行”拒绝。规划失败不会跳过该清扫线，而是按有限重试
进入暂停。若扰动恰好发生在清扫 action 启动后，清扫线最初 `0.75 m` 的兜底门连续
3 个样本确认大横偏/航向误差，再取消 sweep 并走相同恢复路径。

## 冲线与完成

清扫线完成不是命中一个终点圆。补充完成门要求：

- 从本线入口建立连续有向进度历史；
- 至少完成 `90%` 进度并越过出口平面 `0.02 m`；
- 横向误差不大于 `0.30 m`，航向误差不大于 `0.35 rad`；
- 单次位姿跳变不大于 `0.50 m`；
- 新鲜 M2 `/odom` 连续 2 个样本确认线速度不大于 `0.08 m/s`。

因此车辆因制动距离略微冲出终点时，会先停车再完成；不会为了回到精确终点圆而倒车或
绕圈。下一转场直接从实际停车位规划。

## 验证证据与边界

隔离树 `coverage_gz_sim_tree` 保存全部架构对比、A+C 多区域运行及人为入口偏差/冲线
实验。最终 1.20 m 半径真值仿真为 A+C `510.31 s / 240.27 m / 98.95%`，入口恢复分别
约 `1.50 m / 8.174 s` 和 `0.93 m / 8.200 s`，0.55 m/s 冲线最大停车超出
`0.654 m`；所有记录的 footprint、曲率和非零速换档审计均通过。详见：

- [隔离仿真架构](../coverage_gz_sim_tree/CURRENT_ARCHITECTURE.md)
- [架构对比实验](../coverage_gz_sim_tree/EXPERIMENT_REPORT.md)
- [人为异常实验](../coverage_gz_sim_tree/FAULT_INJECTION_EXPERIMENT_REPORT.md)

这些数值不能直接当作 1.35 m 实车结果。正式源码在 1.35 m 配置下完成了 Hybrid
目标区域、稠密曲率采样、cusp/入口状态机和 TEB 硬曲率单元测试；本机 876 项静态验收
零失败，J6M ARM64 install-space 构建和静态健康检查通过。尚未完成的是 1.35 m、真实
定位/轮胎/制动/转向迟滞和动态障碍条件下的不高于 0.3 m/s 受限运动验收。

仿真使用的固定档位纯跟踪器依赖真值 `/odom`，没有被复制到生产控制链。生产当前仍用
TEB 执行单档路径，并由路径偏离、零速和重规划门限制失败范围；因此仿真证明了规划与任务
生命周期，不等于证明 TEB 在实车上的全部跟踪性能。
