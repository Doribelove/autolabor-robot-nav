==================================================

主要实现文件为：

本文只解释“同一区域相邻清扫线之间”的 Hybrid A* 转场。

以下导航阶段不使用本 Hybrid A*：

1. 普通点到点导航：Navfn + TEB。
2. 车辆当前位置到第一条清扫线入口：Navfn + TEB。

4. 沿清扫线直线清扫：强制清扫路径 + TEB。


一、完整计算流程概览
====================

一次覆盖规划的主要计算顺序如下：

步骤 1：对用户圈定的多边形区域生成若干组不同扫描角度的清扫线。

步骤 2：使用时间模型，同时尝试不同的清扫线顺序和每条线的行驶方向。

步骤 3：用宽度为 128 的确定性 beam search 保留时间代价较低的完整路线。

步骤 4：保留最多 4 个完整路线候选。

步骤 5：对每个候选中所有“清扫线之间的转场”运行真实 Hybrid A*。
        第一条清扫线的入场不运行 Hybrid A*，仍保留给 Navfn。

步骤 6：用 Hybrid A* 返回的实际转场代价替换前面的快速估算值。

步骤 7：按以下优先级选择最终完整覆盖路线：

        第一优先级：不可覆盖面积最小。
        第二优先级：预计总清扫时间最短。
        第三优先级：清扫线数量更少。
        第四优先级：用扫描角度作为确定性排序项。

步骤 8：保存所有线间 Hybrid A* 路径，执行过程中不再周期性替换仍然安全的路径。

步骤 9：若 Hybrid 路径中含有前进、倒车换向点，将路径拆成多个单挡位 move_base
        动作。每个换向点先停车，再执行下一挡位子段。


二、搜索状态和车辆运动模型
==========================

2.1 搜索状态
------------

每个 Hybrid A* 状态包含：

    状态 S = (x, y, θ, gear, steering)

各字段含义：

    x, y       车辆在地图中的位置。
    θ          车辆航向角。
    gear       当前运动方向，+1 表示前进，-1 表示倒车。
    steering   当前采用的曲率档位。

状态离散参数：


    位置分辨率                 0.15 m
    航向离散数量               72
    单个航向格大小             360° ÷ 72 = 5°
    转向曲率档位数量           5
    单次运动步长               0.30 m
    碰撞检查采样间隔           0.10 m
    最小转弯半径 R             1.35 m
    最大扩展节点数             80000
    单次规划总超时             1.50 s

状态哈希键同时包含位置格、航向格、挡位和转向档位。因此，同一位置和航向下，
前进到达、倒车到达或采用不同前轮转角到达，会被视为不同状态。这一点使“换向代价”和
“转向变化代价”能够正确累积。


2.2 五档曲率
------------

当前五档曲率为：

    κ ∈ { -1/R, -0.5/R, 0, 0.5/R, 1/R }

代入 R = 1.35 m：

    右满舵曲率       -0.740741 1/m，对应半径 1.35 m
    右半舵曲率       -0.370370 1/m，对应半径 2.70 m
    直行曲率          0
    左半舵曲率        0.370370 1/m，对应半径 2.70 m
    左满舵曲率        0.740741 1/m，对应半径 1.35 m

允许倒车时，每个节点最多产生：

    2 个运动方向 × 5 个曲率 = 10 个后继运动基元

禁止倒车时，每个节点最多产生 5 个前进运动基元。


2.3 圆弧积分
------------

设本次运动距离为 s，运动方向为 gear，曲率为 κ：

    有符号距离 d = gear × s

直行时，也就是 κ = 0：

    x_new = x + d × cos(θ)
    y_new = y + d × sin(θ)
    θ_new = θ

转弯时，也就是 κ ≠ 0：

    θ_new = θ + d × κ

                  sin(θ_new) - sin(θ)
    x_new = x + -----------------------
                            κ

                 -cos(θ_new) + cos(θ)
    y_new = y + ------------------------
                            κ

这不是“先走直线再改角度”，而是直接按照恒定曲率圆弧计算车辆新位姿。


三、A* 排序公式
===============

搜索队列按照以下值从小到大扩展：

    f = g + w × h

其中：

    g    从起点到当前状态的累计实际代价。
    h    从当前状态到目标状态的剩余代价估计。
    w    启发式权重，当前为 1.05。

因此当前实际使用：

    f = g + 1.05 × h

由于 w 大于 1，这属于 Weighted A*。它会稍微优先扩展看起来更接近目标的节点，以减少
扩展数量和规划时间。代价是不能声明严格的数学全局最优，但 1.05 的偏置较小，目标是取得
接近最优的路线，同时满足 1.50 s 的规划时间限制。

注意：最终对外报告的 estimated_time_sec 使用最终路径的 g，而不是 f。
h 只用来决定搜索顺序，不会直接写入最终路径代价。


四、g：已行驶部分的累计代价
============================

4.1 总公式
----------

每扩展一个运动基元，累计代价更新为：

    g_new = g_old + Δg

一个运动基元的代价由五部分组成：

    Δg = T_drive
       + P_steering
       + P_steering_change
       + P_obstacle
       + P_gear_change

也可以写成完整形式：

              Δs
    Δg = -------------
           v_effective

         + 0.04 × |κ| × R

         + 0.10 × |κ - κ_previous| × R

         + 0.25 × C_max

         + 1.00 × I(发生前进/倒车换向)

其中：

    Δs                  本次运动基元长度，格点搜索中固定为 0.30 m。
    κ                   本次运动基元曲率。
    κ_previous          上一个运动基元曲率。
    R                   最小转弯半径，当前为 1.35 m。
    C_max               本基元所有碰撞采样点中的最大归一化代价值。
    I(条件)             条件成立取 1，否则取 0。


4.2 行驶时间 T_drive
---------------------

行驶时间为：

                 Δs
    T_drive = -----------
               v_effective

直行时：

    v_effective = v_gear

转弯时：

                               ω_max
    v_effective = min(v_gear, --------)
                                |κ|

其中：

    v_gear    前进时取当前任务的最大前进速度，倒车时取最大倒车速度。
    ω_max     当前任务允许的最大角速度。

当前 YAML 默认值：

    最大前进速度             0.80 m/s
    最大倒车速度             0.30 m/s
    最大角速度               0.60 rad/s

这些值可以由 Qt 当前任务参数覆盖。当前代码允许的前进速度硬上限是 1.60 m/s。

为什么转弯还要限制线速度：

车辆角速度满足：

    ω = v × |κ|

因此：

         ω_max
    v ≤ -------
          |κ|

若 Qt 把前进最高速度设为 1.20 m/s，车辆以最小半径 1.35 m 转弯时：

    |κ| = 1 ÷ 1.35 = 0.740741 1/m

                        0.60
    角速度允许的线速度 = -------- = 0.81 m/s
                      0.740741

所以这段满舵曲线在代价模型中最多按约 0.81 m/s 计算，而不会按 1.20 m/s 计算。


4.3 持续转向惩罚 P_steering
--------------------------------

计算式：

    P_steering = 0.04 × |κ| × R

五档曲率对应的单个 0.30 m 基元惩罚：

    直行                 0
    半曲率               0.02
    满曲率               0.04

作用：当行驶时间接近时，倾向选择直线或较缓的圆弧。


4.4 转向变化惩罚 P_steering_change
---------------------------------------

计算式：

    P_steering_change = 0.10 × |κ - κ_previous| × R

典型情况：

    直行切换到满左       约 0.10
    满左切换到直行       约 0.10
    满左直接切换满右     约 0.20

作用：抑制前轮在规划路径中频繁左、右来回切换。


4.5 障碍物软代价 P_obstacle
--------------------------------

每个 0.30 m 运动基元内部按照 0.10 m 间隔采样，因此通常至少检查三个中间位姿。
每个位姿均使用完整车辆 footprint，而不是只检查车辆中心点。

对一个采样位姿：

    combined_cost = max(车辆中心栅格代价, footprint 覆盖的最大代价)

归一化：

                       combined_cost
    normalized_cost = ----------------
                            252

并限制在 0 到 1 之间。

一个基元取所有采样点的最大值：

    C_max = max(该基元所有采样位姿的 normalized_cost)

最终软代价：

    P_obstacle = 0.25 × C_max

含义：

    空闲区域                       该项接近 0。
    靠近膨胀障碍物                 该项逐渐变大。
    footprint 碰到致命障碍物       整个运动基元直接作废。
    footprint 进入未知区域         整个运动基元直接作废。
    运动超出 costmap               整个运动基元直接作废。

未知区域不是“代价很高但可以走”，而是明确禁止通行。


4.6 前进/倒车换向惩罚 P_gear_change
---------------------------------------

当前后两个运动基元的 gear 不同：

    P_gear_change = 1.00 s

否则：

    P_gear_change = 0

第一次从根节点选择前进或倒车时不收取换向惩罚，因为此时 previous gear 为 0。

例如车辆已经前进，下一基元改为倒车直行：

    倒车行驶时间 = 0.30 ÷ 0.30 = 1.00 s
    换向附加时间 = 1.00 s

若忽略障碍物和转向项，该倒车基元新增代价为：

    Δg = 1.00 + 1.00 = 2.00

这使算法不会为了节省很短的几何距离而随意增加换向动作。


4.7 数值示例
------------

示例 A：空旷区域直行前进一个基元

    Δs = 0.30 m
    v = 0.80 m/s
    κ = 0
    不换向
    C_max = 0

    Δg = 0.30 ÷ 0.80 = 0.375


示例 B：从直行切换到满左前进一个基元

    行驶时间             0.30 ÷ 0.80 = 0.375
    满曲率持续转向惩罚   0.04
    直行到满左变化惩罚   0.10
    空旷区域障碍物代价   0
    不换向               0

    Δg = 0.375 + 0.04 + 0.10 = 0.515


示例 C：障碍物膨胀区附近的满左基元

假设 C_max = 0.80：

    障碍物软代价 = 0.25 × 0.80 = 0.20

若其他条件与示例 B 相同：

    Δg = 0.375 + 0.04 + 0.10 + 0.20 = 0.715


五、h：剩余路程的启发代价
==========================

5.1 总公式
----------

h 不是单独的欧氏距离，而是多个“剩余时间估计”的最大值：

    h = max(T_distance,
            T_yaw,
            T_curvature,
            T_Reeds_Shepp,
            T_obstacle_grid)

取最大值而不是相加的原因：车辆在向目标移动的同时可以改变航向。如果把距离时间、转向时间
全部相加，会重复计算同一段运动，容易高估剩余代价。


5.2 欧氏距离时间 T_distance
--------------------------------

设当前位置到目标位置的直线距离为：

    D = sqrt((x_goal - x)² + (y_goal - y)²)

用于启发函数的最大线速度为：

    v_fastest = max(最大前进速度, 允许倒车时的最大倒车速度)

一般情况下前进速度更快，所以 v_fastest 等于最大前进速度。

计算式：

                       D
    T_distance = -------------
                   v_fastest


5.3 航向角时间 T_yaw
-----------------------

设当前航向和目标航向之间的最小角度差为 |Δθ|：

                     |Δθ|
    T_yaw = ----------------
                   ω_max

例如航向还差 180°，最大角速度为 0.60 rad/s：

    |Δθ| = π rad

    T_yaw = π ÷ 0.60 ≈ 5.24 s

这只是时间下界，不表示前轮转向车辆能够原地旋转。


5.4 最小转弯半径时间 T_curvature
------------------------------------

改变 |Δθ| 航向至少需要约 R × |Δθ| 的圆弧长度，因此：

                       R × |Δθ|
    T_curvature = -------------------
                         v_fastest

这一项避免把“位置很近但车头方向完全相反”的状态误认为几乎没有剩余代价。


5.5 Reeds–Shepp 非完整约束启发 T_Reeds_Shepp
------------------------------------------------

允许倒车且该项启用时，计算无障碍环境下从当前完整位姿到目标完整位姿的最短
Reeds–Shepp 几何路径长度 L_RS：

                          L_RS
    T_Reeds_Shepp = ----------------
                       v_fastest

它考虑：

    起点位置和航向。
    终点位置和航向。
    最小转弯半径。
    前进和倒车组合。

它故意不计入：

    倒车速度比前进速度慢的额外时间。
    换向附加时间。
    转向及转向变化惩罚。
    障碍物软代价。

原因是 h 应尽量保持乐观，用最快速度除以几何长度可以避免人为高估。

若搜索开始时已经得到一个有效的直接 Reeds–Shepp 路径上界，后续每个节点不再重复计算
昂贵的 Reeds–Shepp 启发，以减少规划时间。


5.6 二维障碍物 Dijkstra 启发 T_obstacle_grid
------------------------------------------------

算法从目标点开始，在 costmap 上反向进行一次八邻域 Dijkstra，得到每个二维栅格到目标的
已知自由空间距离 D_grid：

                              D_grid
    T_obstacle_grid = --------------------
                            v_fastest

这个二维 Dijkstra：

    禁止穿过致命障碍物。
    禁止穿过未知区域。
    允许八邻域和对角移动。
    不考虑车辆航向。
    不检查完整车体 footprint。
    不把膨胀代价作为额外距离累加。

它的作用是告诉 Hybrid A* 静态障碍物大致应该从哪一侧绕行。车辆运动学、完整 footprint
碰撞和膨胀区软代价仍由实际 g 扩展检查负责。

栅格离散距离可能比连续路径稍大，因此代码只用它进行搜索队列排序，不用它进行严格的
解析上界剪枝。进行解析上界剪枝时，使用不带二维 Dijkstra 的连续下界。


六、Reeds–Shepp 解析候选和 Hybrid 格点搜索的配合
===================================================

6.1 直接解析候选
----------------

规划开始时，算法枚举所有有效 Reeds–Shepp 类型及其对称形式，最多约 48 类候选。

每条候选均会：

    按 0.10 m 间隔检查完整 footprint。
    拒绝致命障碍、未知区域和地图外路径。
    按前进速度、倒车速度和最大角速度计算行驶时间。
    计算持续转向惩罚。
    计算转向变化惩罚。
    计算障碍物软代价。
    计算前进/倒车换向次数和换向附加时间。
    精确连接到目标位置和目标航向。

因此解析候选不是单纯选择“几何长度最短的 Dubins 圆弧”，而是对所有碰撞可行候选使用与
格点搜索相同的时间型代价进行比较。


6.2 解析候选作为搜索上界
--------------------------

如果直接解析候选有效，且它的代价没有超过最短几何 Reeds–Shepp 乐观时间的两倍：

    direct_cost ≤ 2 × direct_lower_bound

则把它作为当前可行上界。

Hybrid A* 随后继续短时间搜索，尝试找到：

    更少换向的路径。
    时间代价更低的路径。
    更适合障碍物分布的路径。
    转向变化更平缓的路径。

开放或简单场景的默认改进窗口为 0.20 s。

若直接解析路径含有换向，而且几何关系显示可能存在更平滑的前进绕行路线，改进窗口可延长
到 0.65 s。

没有直接解析上界时，每扩展 200 个节点尝试一次从当前节点到精确目标的 Reeds–Shepp
解析连接。首次找到此类连接后，再保留最多 0.50 s 的改进窗口。

所有搜索仍受 1.50 s 总超时和 80000 扩展节点上限约束。


6.3 目标容差和末端连接
----------------------

当前格点节点进入以下范围时：

    位置误差 ≤ 0.30 m
    航向误差 ≤ 0.40 rad，约 22.9°

不会把精确目标点直接硬追加到路径末尾。

正确流程是：

    进入目标容差范围
        ↓
    尝试从当前完整位姿到精确目标完整位姿的 Reeds–Shepp 连接
        ↓
    按 0.10 m 采样并检查完整 footprint
        ↓
    验证全程曲率不超过 1/R
        ↓
    有效后才接受为最终末端

这样可以避免旧逻辑中最后一小段出现急折线或原地改变航向，导致 TEB 无法跟踪。

运行时 move_base 仍可按照入口位置和航向容差完成动作，不要求实车压到数学上的零误差。
“规划路径精确且运动学连续”和“实车在合理容差内完成”是两个不同层面的要求。


七、换向次数与时间代价的最终取舍
==================================

最终选择并非只比较一个浮点总代价，还额外偏好更少的前进/倒车换向。

候选换向次数更少时：

    candidate_cost ≤ 1.05 × current_cost

即可接受。也就是说，更少换向的路线即使最多慢约 5%，仍可能获选。

候选换向次数更多时，必须满足：

    1.05 × candidate_cost < current_cost

也就是新增换向必须带来明显超过约 5% 的代价改善，才允许替换当前路线。

换向次数相同时：

    直接选择总代价更低的路线。

设计目的：避免为了节省极少的理论时间，生成“前进—倒车—前进”的复杂动作，从而增加
停车、换挡、前轮摆动和 TEB 跟踪风险。


八、已有解析上界时的节点剪枝
==============================

设已经找到一条解析路径，其总代价为 best_analytic_cost。

对于新节点，计算：

    optimistic_total = candidate_g + continuous_lower_bound

如果新节点的换向次数不少于当前解析路径，并且：

    optimistic_total ≥ 1.05 × best_analytic_cost

则该节点不再加入搜索队列。

这里的 continuous_lower_bound 只使用连续距离、航向和曲率下界，不使用可能受栅格离散
影响的二维 Dijkstra 距离。

若新节点的换向次数更少，则不会被上述条件直接剪掉，因为它仍可能在允许的 5% 时间范围内
成为更易执行的最终路径。


九、整条覆盖路线的总代价
========================

9.1 初步路线排序
----------------

当前正式架构不做任务级 Hybrid A* 预计算。上层使用快速时间模型评估清扫线顺序和方向，
只输出有向清扫线列表，不输出可执行连接路径。

一段从静止到静止的直线运动时间采用对称梯形或三角速度模型。

设距离为 D，最高速度为 v，加速度为 a。

达到最高速度所需的完整加减速距离为：

                 v²
    D_ramp = --------
                  a

当 D ≥ D_ramp，能够达到最高速度，时间为：

                    D     v
    T_motion = -------- + ---
                    v     a

当 D < D_ramp，只能形成三角速度曲线，时间为：

                         D
    T_motion = 2 × sqrt(---)
                         a

第一个入口与后续转场使用不同的距离来源：

    第一个入口：静态已知自由空间距离，近似实际 Navfn 入场。
    后续转场：Dubins 最小转弯半径几何距离，不调用静态 A*。

首入口先保留静态最短距离 + 0.30 m 的端点，再保留最佳估计时间 + 1.0 s 的候选。
其余完整路线代价还会结合：

    前进和倒车速度差异。
    最大角速度和角加速度。
    每次换向附加时间。
    每段交接附加时间。

beam search 宽度为 128，会同时选择：

    从哪一条清扫线开始。
    后续清扫线顺序。
    每条线从哪一头进入。
    清扫线本身的行驶方向。


9.2 在线执行，而不是任务级重新评分
------------------------------------

beam search 选出一条确定的完整路线后不再用真实 Hybrid A* 重新评分，也不保留四条
候选轨迹。区域首线执行一个 Navfn + TEB 普通导航 action；每次完成清扫线后，才从实时
停车位向已选下一入口调用一次 Hybrid A*。所以任务级选择不会因地图 A* 或 Hybrid 搜索
长时间阻塞，实际连接也不会使用任务开始时的陈旧位姿。

整条路线预计时间为：

    T_proxy = T_first_entry_known_free
            + ΣT_sweep
            + ΣT_Dubins_transit
            + ΣT_handoff

该值是线序选择代理，不是已经生成的可执行全局轨迹，也不保证等于动态执行时间。实际
Hybrid 路径、cusp 数和事件重规划只有到相应转场时才产生。


十、规划结果如何交给 TEB
========================

Hybrid A* 输出的是全局参考路径，不直接输出底盘控制量。

执行链路为：

    Hybrid A* 全局参考路径
        ↓
    按前进/倒车符号识别换向点
        ↓
    在每个换向点拆成单挡位 move_base 子动作
        ↓
    TEB 在局部 3.0 m 前视范围内跟踪
        ↓
    TEB 根据实时局部代价地图避障和微调轨迹
        ↓
    /cmd_vel 安全门和底盘执行

正向 Hybrid 子段禁止 TEB 倒车；反向 Hybrid 子段允许倒车并取消纯前进偏好。

中间换向点完成容差：

    位置误差 ≤ 0.12 m
    航向误差 ≤ 0.15 rad，约 8.6°

最终清扫线入口完成容差：

    位置误差 ≤ 0.30 m
    航向误差 ≤ 0.40 rad，约 22.9°

由于 TEB 当前 free_goal_vel 为 false，每个换向点会先达到零终速，再提交下一挡位子动作。


十一、Qt 参数与计算位置
======================

以下参数会进入当前任务的 Hybrid A* 时间型代价：

    是否允许倒车。
    最大前进速度。
    最大倒车速度。
    最大角速度。

以下参数进入上层整条路线时间模型和 TEB，但当前没有直接进入 Hybrid A* 内部的 g 或 h：

    最大角加速度。
    每段交接附加时间。

十二、当前算法的准确含义和限制
============================

1. estimated_time_sec 是“时间型参考代价”，不是严格的实车秒表时间。

   行驶距离除以有效速度、每次换向附加时间都具有明确的秒数意义；但转向惩罚和障碍物软代价
   是人为权重，用于提高平滑性和安全余量。因此最终数值是以秒为主体的混合参考代价。

2. Hybrid A* 内部尚未直接积分线加速度和角加速度。

   加速度当前用于上层整条覆盖路线的启停时间估计，并传给 TEB 作为实际执行约束。
   Hybrid A* 内部每个固定 0.30 m 基元使用有效稳定速度近似。

3. Hybrid A* 没有调用 TEB 图优化代价来选择全局路径。

   TEB 的原始图优化目标由多种残差权重组成，不是物理秒数，不能直接加到 Hybrid A* 的
   时间目标中。当前架构是 Hybrid A* 选择全局运动学可行路线，TEB 在执行时局部跟踪避障。

4. Weighted A* 权重为 1.05。

   它优先保证在 1.50 s 内得到接近最优且可执行的路径，而不是无限搜索严格最优解。

5. 最终选择额外偏好更少换向。

   因此最终路线不是单纯的最小 g，而是“总代价接近时优先少换向”。这是针对 M2 前轮转向
   底盘实际停车换挡和跟踪稳定性作出的工程选择。

6. 静态障碍来自规划时冻结的一份全局代价地图快照。

   执行过程中出现的动态人员或新障碍由局部代价地图和 TEB 处理。如果缓存 Hybrid 路径被
   完整 footprint 判定为受阻，才会触发在线 Hybrid 重搜。

十四、阅读一次规划结果时应关注的统计量
====================================

HybridTransitionResult 会返回：

    estimated_time_sec      最终选中路径的累计时间型 g 代价。
    reverse_distance_m      路径中的累计倒车距离。
    direction_changes       前进/倒车换向次数。
    expansions              Hybrid 格点搜索扩展的有效节点数。
    path                    碰撞检查和曲率检查均通过的完整路径。
    reason                  选择解析路径、格点路径或规划失败的原因。

判断一次规划是否健康时，不能只看几何路径是否漂亮，还应同时查看：

    是否接近 1.50 s 超时。
    扩展节点数是否异常增大。
    是否产生不必要的倒车距离。
    是否产生多个换向点。
    路径是否长时间贴近高膨胀代价区域。
    TEB 是否能在 3.0 m 前视下稳定跟踪该路径。


十五、结论
==========

当前 Hybrid A* 的核心目标可以概括为：

    在完整车体不进入障碍物和未知区域、满足 1.35 m 最小转弯半径的前提下，
    优先寻找预计行驶时间较短、障碍距离更安全、转向变化更少且换向次数更少的
    相邻清扫线转场路径。

它不是单纯最短距离算法，也不是直接最小化 TEB 内部图优化代价。它采用时间型 g、多个
乐观时间下界组成的 h、Reeds–Shepp 解析上界以及少换向偏好，共同在有限规划时间内生成
适合 M2 前轮转向底盘执行的全局转场参考路径。
