## move_base 能力核对

本项目原有链路为AI MCP → `move_base_pause_bridge.py` → move_base → CoverageGlobalPlanner普通模式中的Navfn → TEB。

原版不支持直接以省略四元数的 `(x,y)` 目标表达任意朝向：move_base接收 `PoseStamped` 并校验四元数；全零四元数无效，单位四元数表示yaw=0。TEB原有成功条件同时检查XY误差、yaw误差和停车条件，优化也使用目标朝向。仅让大模型不填yaw或全局放宽yaw容差不能完整表达每目标独立的自由朝向。

对照本项目修改前 `043e28d` 的 `teb_local_planner_ros.cpp`，以及上游 [move_base目标处理](https://github.com/ros-planning/navigation/blob/noetic-devel/move_base/src/move_base.cpp)。TF转换不保留目标Header.seq，因此不能只靠输入seq将自由朝向信息直接传到规划器。

另核对 [OdometryHelperRos](https://github.com/ros-planning/navigation/blob/noetic-devel/base_local_planner/src/odometry_helper_ros.cpp)：其只缓存速度及child_frame_id，不保留Header.stamp。新到点停车判定必须自行保留带时间戳的里程计，不能把辅助类的零时间戳误判为新鲜反馈。

## 本地实现

- 视觉初始捕获锚点纵向比例改为闭区间 **0.05～0.90**；配置、节点默认值、参数合法范围同时修改。原有效深度、置信度、水平范围、连续6帧锁定及安全保护保留。0.953和更靠底部的目标仍超出用户本次指定范围。
- AI清扫成功由本次会话的新COMPLETE回执决定；不在AI另设距离、角度或图像位置条件。`cleaning_completed`与`ready_for_next_step`分开：控制器清扫完成后，继续等待新鲜停车回执及导航控制权归还，再允许下一步。ABORT、取消及旧回执不能成功。
- 未指定目标朝向时，MCP导航角度参数可省略；明确角度（包括0度）必须保留。返回本轮冻结位置默认只固定x/y；明确“保持原来朝向”才约束为快照yaw。相对位移无转角时也默认最终朝向不限，其目标用新鲜map定位换算。
- 新增 `SetOrdinaryGoalPolicy.srv`，导航桥预检后在状态锁外有界登记策略，再在原所有权锁内复核并发送原明确GoalID。登记期间取消、暂停仍能及时处理，复核拒绝发送已取消目标；延迟到达的旧登记不能覆盖更新的策略。全局规划器按同一J6M时间戳、坐标系及完整位姿严格匹配，在普通Navfn输出上携带每目标策略序号；不修改全局TEB容差。固定朝向目标、Qt目标及覆盖路径不继承该策略。
- TEB对带有效策略的普通目标按路径选择接近方向；进入原XY容差后发送零速，等待新鲜物理停车，不要求终点yaw。停车前、陈旧零速反馈、XY未到达均不成功。仍由move_base返回原GoalID的SUCCEEDED，AI不把取消伪装成到达。
- MCP、桥及两规划器配套协议缺失时拒绝自由朝向目标；旧J6M版本不能只重开新版AI后混用。
