一、系统是做什么的
------------------

本系统使用 SAC 强化学习在线调节 TEB 局部规划器参数。

SAC 不直接控制车辆，也不直接发布 /cmd_vel。车辆仍由 move_base + TEB 控制，
SAC 只以较低频率提出 TEB 参数调整建议。

整体流程：

  ROS/Gazebo 传感器与导航状态
    -> 状态构造与 4 帧历史窗口
    -> SAC 策略
    -> 生成 9 个 TEB 参数候选
    -> 参数投影和变化率限制
    -> 安全状态机与保守回退
    -> dynamic_reconfigure 原子写入 TEB
    -> TEB 重新规划并控制机器人
    -> 计算 reward、成本并保存训练数据


二、状态空间
------------

SAC 每次接收一个 254 维状态：

  254 = 4 x 61 + 10

每一帧 61 维，包括：

  1. 36 维激光雷达扇区距离；
  2. 障碍物净空、密度和 TTC；
  3. 目标距离和方向；
  4. 路径横向误差和航向误差；
  5. 线速度、角速度和线加速度；
  6. planner、sensor、TF、定位和参数接口有效标志；
  7. 当前 9 个 TEB 参数。

系统连续保存 4 帧，使 SAC 能观察障碍物、速度和路径误差的变化趋势。

最后 10 维包括：

  - 上一步真正生效的 9 个归一化 TEB 参数变化；
  - 这 9 个变化量的绝对值总和。

这里使用“实际生效变化”，因为 SAC 原始动作可能被投影或安全模块限制。


三、障碍物特征
--------------

1. 障碍物净空

  障碍物到机器人车体边缘的最近距离，不是到激光雷达中心的距离。
  净空越小，碰撞风险越高。

2. 障碍物密度

  当前计算为 2 米内有效激光点数除以全部有效激光点数。
  接近 0 表示环境空旷，接近 1 表示周围比较拥挤。

3. TTC（Time To Collision）

  当前近似为：

    TTC = 障碍物净空 / max(当前速度绝对值, 0.05)

  TTC 越小，表示按当前速度继续运动时风险越紧迫。
  这只是工程近似，尚未完整考虑动态障碍物和转向轨迹。


四、9 个 TEB 参数
-----------------

1. max_vel_x
   最大前进速度。调大后行驶更快，但安全余量下降。

2. max_vel_theta
   最大旋转角速度。调大后转向更快，但可能不够平滑。

3. acc_lim_x
   最大线加速度。调大后加减速更快，但动作可能更突然。

4. acc_lim_theta
   最大角加速度。调大后转向响应更快，但可能增加摆动。

5. min_obstacle_dist
   规划轨迹与障碍物的最小距离。调大后更保守，但可能无法通过窄通道。

6. inflation_dist
   障碍物影响范围。调大后会更早绕障，但可用通行空间减少。

7. weight_obstacle
   TEB 优化中避障项的权重。调大后更重视远离障碍物。

8. weight_viapoint
   跟随全局路径参考点的权重。调大后更贴近全局路径，但绕障灵活性降低。

9. weight_optimaltime
   时间最优项权重。调大后更重视快速到达，规划可能更激进。

可将它们分为三类：

  - 运动能力：速度、角速度、线加速度、角加速度；
  - 安全距离：最小障碍距离、膨胀距离；
  - 规划偏好：避障、路径跟踪和时间最优权重。


五、两种 SAC 动作空间
---------------------

1. Semantic-Eta（论文方法）

  输出 5 维语义增量：

    - 速度偏好；
    - 避障保守性；
    - 安全距离偏好；
    - 路径跟踪偏好；
    - 平滑性偏好。

  动作范围为 [-1, 1]^5，然后通过 T07 标定并冻结的 A_TEB 矩阵转换成
  9 个归一化 TEB 参数变化。

2. Direct-Theta（公平对照）

  直接输出 9 个归一化 TEB 参数变化，动作范围为 [-1, 1]^9。

两组共享完全相同的：

  - 254 维状态；
  - reward；
  - 场景和 seed；
  - SAC 隐藏层；
  - 训练步数；
  - 参数投影和安全过滤；
  - checkpoint 和评估流程。

唯一主要差别是 5 维语义动作与 9 维直接参数动作。


六、动作安全链
--------------

SAC 输出不会直接写入 TEB，而是依次经过：

  SAC 动作
    -> 维度和 NaN/Inf 检查
    -> 归一化参数范围裁剪
    -> 反归一化为物理参数
    -> 物理上下界限制
    -> 单步变化率限制
    -> 参数耦合检查
    -> 安全状态机
    -> 必要时使用保守参数回退
    -> 原子写入 TEB
    -> ACK 和 readback 验证

安全状态机包含：

  NORMAL -> WARNING -> EMERGENCY -> FAULT

出现危险或接口故障时，系统会停止正常学习写入，并使用完整的保守参数配置回退。
每个 episode 结束后恢复启动参数快照，避免训练参数污染后续实验。


七、训练和 checkpoint
---------------------

当前训练环境固定使用：

  - Python 3.8.10；
  - PyTorch 2.4.1+cpu；
  - Gymnasium 1.0.0；
  - Stable-Baselines3 2.4.1；
  - CPU-only，CUDA 禁用。

checkpoint 保存：

  - model.zip；
  - replay_buffer.pkl；
  - vecnormalize.pkl；
  - checkpoint_manifest.yaml。

加载时验证文件 SHA256、算法身份、依赖版本和 CPU 运行环境，因此可以恢复训练，
而不只是加载模型做推理。

九、目前的主要难点
------------------

1. 参数写入后需要等待 TEB 真正重新规划，reward 不能从请求时刻立即计算。

2. SAC 原始动作可能被投影和安全层修改，因此必须区分 candidate、projected、safe
   和 applied 参数。

3. Semantic-Eta 和 Direct-Theta 必须保持状态、reward、预算和安全链公平一致。

4. A_TEB 不能凭经验填写，需要由 Gazebo 正负扰动和敏感性数据生成。

5. 当前 M2 Gazebo 模型是确定性运动学模型，没有完整模拟轮胎、侧滑、悬挂、
   转向滞后和真实制动动力学。

6. 当前动作经常可能触发变化率投影，正式训练前需要冻结统一的动作缩放设计。

7. 当前安全范围仅为 Gazebo 候选，不能直接作为实车安全结论。
