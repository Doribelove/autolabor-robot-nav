# 第 4 章 实验完整性与可复核方法

## 4.1 为什么完整性本身是研究方法

机器人导航实验同时依赖场景文件、启动脚本、参数合同、随机种子、运行时服务、模拟时钟和结果解析器。只保存最终均值并不能回答以下问题：运行时使用的是否是预注册文件；失败样本是否被替换；评估器是否读取了执行后被修改的资源；“没有 TTC”究竟来自场景运动，还是来自启动顺序、日志缺失或解析错误。对于样本量有限、执行成本较高的实验，这些问题足以改变论文结论。

因此，本研究把实验完整性定义为一组可机器检查的不变量，而不是事后整理日志。其目标是建立从研究问题到论文陈述的可追踪链：

\[
\text{design}
\rightarrow
\text{authorization}
\rightarrow
\text{release}
\rightarrow
\text{journal}
\rightarrow
\text{raw evidence}
\rightarrow
\text{assessment}
\rightarrow
\text{claim}.
\]

链上任一必要门失败，执行或结论都必须失败关闭。完整性方法不能保证算法有效，却能防止未经授权的运行、证据漂移和超出设计效力的表述被误认为算法结果。

## 4.2 预注册与阶段状态机

### 4.2.1 不可混淆的文档角色

每个受控阶段把下列角色分开：

- **design**：研究问题、因素、指标、停止规则和未来计划；
- **preregistration**：执行前冻结的方法、场景、种子角色、统计与 claim rule；
- **authorization**：用户明确许可的执行身份、预算和边界；
- **release**：把授权与精确依赖哈希闭合为唯一可执行对象；
- **journal**：追加记录每个预算单元的生命周期；
- **assessment**：只依据冻结证据作确定性判定；
- **handoff**：总结状态和下一安全入口，但本身不授予执行权限。

设计文件不能替代授权，授权也不能在依赖未闭合时替代 release。特别地，“论文需要性能结论”是研究目标，不是执行授权，更不是修改停止规则的理由。

### 4.2.2 状态迁移

受控执行采用单向状态迁移：

```text
DESIGNED
  -> PREREGISTERED
  -> AUTHORIZED
  -> RELEASE_VALIDATED
  -> PREJOURNAL_PASS
  -> STARTED
  -> TERMINAL
  -> ASSESSED
```

任一阶段可以进入 `FAILED_CLOSED` 或 `TERMINALLY_STOPPED`，但不能回到先前身份继续使用。修复必须建立新的独立阶段、身份和审查，不能覆盖失败 release 或复用已消费/已作废的种子预算。

## 4.3 新鲜种子防火墙与预算原子性

### 4.3.1 角色化种子

随机种子按用途分区：开发、编译支持、确认性执行和 held-out 评估互不复用。种子不是一个可随意挑选的整数，而是 `(stage, scene-role, seed, method, attempt)` 身份的一部分。执行器只接受预注册 schedule 中的精确组合。

同一 scene-seed block 内的方法共享场景随机实现，从而形成配对；不同 block 才作为独立随机单位。统计分析以 block 为单位，避免把高频传感器样本或同一 episode 内的时间点伪装成独立样本。

### 4.3.2 单元消费规则

预算单元在 attempt 身份写入 canonical journal 后即进入不可替换生命周期。其结果可以是成功、碰撞、超时、启动失败或完整性失败，但不得通过以下方式删除不利结果：

- 使用同一身份重试；
- 换 seed 补齐样本；
- 从摘要中忽略失败 episode；
- 在看到结果后延长超时；
- 追加样本直到显著；
- 把部分完成的 journal 当作未开始。

若系统故障发生在语义执行前，阶段规则决定该单元是 consumed 还是 forfeited；判定由 journal 事件和预注册定义产生，而不是由结果好坏产生。

## 4.4 规范路径与哈希依赖闭包

### 4.4.1 路径约束

每项授权资源以 workspace 内规范相对路径标识。验证器要求：

1. 路径解析后仍位于指定 workspace；
2. 文件本身及关键路径段不是符号链接；
3. 资源类型与合同一致；
4. 不接受 `..` 逃逸、重复别名或运行时重新定位；
5. runtime binding 指向预先声明的目标。

这些约束防止同一文本路径在审查与执行时解析到不同资源。

### 4.4.2 依赖有向图

将资源记为节点集合 $V$，依赖关系记为有向边 $E$。每个节点绑定内容哈希

\[
h(v)=\operatorname{SHA256}(\operatorname{bytes}(v)).
\]

release 绑定 preregistration、authorization、runner、scene derivation、evaluator、assessor、launch 文件和必要 runtime target 的 `(canonical path, SHA-256)`。验证通过要求：

\[
\forall v\in V_{\mathrm{authorized}},
\quad
h_{\mathrm{current}}(v)=h_{\mathrm{release}}(v),
\]

并且 schema 中没有未声明字段、遗漏依赖或额外可执行资源。这样，审查结论针对的是一组精确字节，而不是会继续变化的文件名。

### 4.4.3 解析范围与类型敏感性

并非每个历史 YAML 都适合由新验证器重新解释。一次失败的预检表明，遗留场景派生文件含整数 seed key，而通用验证器错误要求所有授权 YAML 的 key 都为字符串。修复后的原则是：

- 对当前阶段需要理解语义的少数合同进行严格解析；
- 对其余冻结历史资源只验证原始字节哈希；
- 不以新 parser 的偏好改写历史文件；
- 对被解析 YAML 拒绝 duplicate key、隐式类型混淆和 schema 外字段。

这既保留旧证据，又避免“能通过哈希但解析为另一种含义”的模糊性。

## 4.5 单次打开、禁止跟随与 TOCTOU 防护

若程序先按路径计算哈希，再次打开同一路径解析，两个时刻之间可能发生替换，形成 time-of-check/time-of-use 风险。关键合同采用以下策略：

1. 使用禁止跟随符号链接的方式打开目标；
2. 验证打开后文件描述符对应的对象类型；
3. 从同一份已读取字节同时计算哈希和解析内容；
4. 在生命周期内不按路径重新读取该合同；
5. 将实际读取哈希写入 journal。

因此，验证器判断的字节与执行器使用的字节保持一致。该机制不能防御拥有更高系统权限的恶意内核或存储层，但覆盖了本工作区内普通文件替换和符号链接切换风险。

## 4.6 模拟时钟 bootstrap 完整性

ROS 仿真中的 readiness 不等于进程存在。历史执行曾出现如下顺序死锁：runner 在 Gazebo 仍暂停时等待 `move_base` 动态配置服务，而解除暂停操作被安排在这次等待之后。结果是服务等待超时，语义 episode 根本没有开始。

修复后的 bootstrap 把“时钟取得正进展”设为独立屏障：

1. 启动必要模拟基础设施；
2. 读取 `/clock` 基准值；
3. 执行预声明的解除暂停动作；
4. 要求 `/clock` 在有限 wall-clock 窗口内严格增加；
5. 之后才等待 `move_base`、动态配置服务和导航 readiness；
6. 任一条件失败则在创建语义执行状态前失败关闭。

这里检查的是正进展，而不是仅检查 `/clock` topic 存在。I5 的每个运行均保存多次直接 readiness 观测，以减少单点瞬态造成的误判。

## 4.7 运行时授权与凭据隔离

执行器仅允许 release 中精确绑定的 schedule、scene role、method、seed 和 attempt。schema 对布尔值、整数、字符串保持类型敏感，例如字符串 `"false"` 不能代替布尔 `false`。执行身份之外的额外参数必须拒绝，而不是采用默认值。

子进程环境采用显式 allowlist。与实验无关的凭据变量不传递给 ROS、Gazebo 或日志工具；日志也不记录完整环境。测试使用合成凭据标记验证脱敏行为，但不保存真实 token。该措施同时降低凭据泄露风险和由用户 shell 环境引入不可复现实验差异的风险。

## 4.8 事务化 journal 与原始证据

### 4.8.1 事件模型

每个预算单元的 journal 至少记录：

- 不可变身份与 schedule 行；
- release 和关键依赖哈希；
- `STARTED` 时间与 readiness 证据；
- 参数事务和导航结果；
- TTC 语义计数与原始文件绑定；
- `TERMINAL` 状态、失败类别、consumed/forfeited 判定；
- teardown 和进程隔离结果。

写入采用临时文件、同步和原子替换，避免半截 YAML 被误识别为完整终态。journal 是生命周期事实来源；汇总报告必须能从 journal 和 raw resources 重建。

### 4.8.2 直接计数而非摘要自证

对于 readiness、TTC 和语义状态，assessor 不仅读取 runner 汇总的计数，还直接读取绑定的原始 topic/log 资源重新计数。设 runner 声明计数为 $n_s$，重放计数为 $n_r$，则通过要求

\[
n_s=n_r
\]

并满足预注册的最小样本数和状态关系。摘要不能用自己的结论证明自己。

## 4.9 确定性评估器

assessor 是只读函数：给定冻结 journal、raw resources 和合同，应产生逐字段相同的报告。其必要性质包括：

- 不访问网络、不启动 ROS、不依赖当前模拟状态；
- 不修改输入或创建执行身份；
- 对输入采用封闭 schema 和哈希校验；
- 对排序、浮点格式和缺失值使用固定规则；
- `--check-only` 将当前重建结果与持久化报告精确比较；
- 任一绑定、计数或状态不一致即失败。

I5 的确定性重放覆盖 6 项 journal binding 和 36 项原始资源 binding，最终报告未发现完整性失败。后续离线解释阶段再次从这些资源重建六个单元的语义计数，并与持久化解释报告逐字段比较。

## 4.10 失败证据保全与修复链

本研究保留了多类失败：冲突未进入预测窗口、模拟时钟 bootstrap 死锁、外部哈希闭包不完整、authorization assessor 失效，以及遗留 YAML key 类型导致的 prejournal 拒绝。每次修复遵循三条规则：

1. 原失败文件、release、journal 和哈希保持不变；
2. 修复发生在新的独立阶段，获得新的审查身份；
3. 修复通过离线回归后，仍需单独的未来执行授权。

这条历史链使论文能够区分算法语义失败与实验基础设施失败，也避免把修复后的成功反向覆盖到原失败身份。

## 4.11 终态隔离

一次 episode 完成并不代表实验终态完整。受控 teardown 检查 ROS master、Gazebo、`move_base`、runner 和相关子进程是否退出，并保存结果。下一单元只在前一单元隔离通过后开始。最终报告还需确认没有训练进程、真实车辆接口或非计划参数写入。

I5 六个单元结束后，ROS/Gazebo/导航相关进程均处于清洁终态。该结论只说明进程隔离，不说明真实车辆运行安全。

## 4.12 从证据到论文陈述的 claim gate

论文陈述按效力分层：

| 层级 | 所需证据 | 当前状态 |
|---|---|---|
| 组件正确性 | 单元测试、schema、静态审查 | 已有 |
| 执行集成正确性 | 新鲜种子、完整事务、直接计数、确定性重放 | I5 已通过 |
| 模拟性能提升 | 预注册多种子配对统计、安全非劣和机制门 | 尚未执行 |
| 跨场景泛化 | 独立 held-out 分布与外部复核 | 未建立 |
| 真实车辆效果 | 现场审批、实车合同和安全验证 | 未授权 |
| 形式化安全 | 可证明模型、假设和验证 | 不在本研究当前证据中 |

因此，集成通过不能自动升级为性能提升；统计显著也不能自动升级为安全或实车泛化。每个结论只能停留在其证据层级。

## 4.13 最终性能实验的完整性约束

未来性能设计预注册 3 个 scene role、每个 30 个全新 scene-seed block，共 90 个 block。circle-contact 与 legacy control 构成主配对；固定 TEB 只作背景参照。确认性分析必须遵循：

1. 所有 block 按精确 schedule 运行，不重试、不替换；
2. 失败和超时以预注册惩罚进入受限完成时间；
3. 先检查完整性门；
4. 再检查成功率、碰撞率、最小间距和真实冲突保持的非劣门；
5. 再检验分层配对 log-time 效应；
6. 最后检验错误冲突触发减少这一机制；
7. 只有全部门通过，才允许在限定的新鲜模拟动态交互分布上写“性能提升”。

样本量和阈值在结果出现前固定。连续效率终点的功效假设要求每个 role 至少约 22 对，预注册取 30 对。二元成功/碰撞非劣采用按 role 分层后的 90-block pooled interval，同时要求每个 role 的 treatment harmful discordance 不多于 control；零 harmful discordance 时 90-block 单侧精确上界约为 3.28%，60 个真实冲突 block 的对应上界约为 4.87%。因此 5 percentage-point margin 只有在伤害差异极低时才可能通过，不会因连续终点显著而自动通过。设计不增加训练预算，也不允许基于 I5 的六个集成单元估计或挑选有利效应量。未来结果若未通过任何一门，应报告未证实或出现权衡，而不是改变指标或追加样本。

## 4.14 有效性威胁与边界

完整性闭包主要处理可复现性和选择偏差，仍有以下限制：

- SHA-256 证明字节一致，不证明文件内容科学正确；
- deterministic assessor 可能与 runner 共享概念性错误，因此需要独立测试和人工审查；
- 模拟器、ROS 和系统库版本仍可能影响外部复现，应在最终环境清单中记录；
- 配对随机种子减少场景方差，但不能覆盖全部动态参与者行为；
- 三个 scene role 的结果只适用于其预注册分布；
- 固定超时惩罚影响受限完成时间解释，必须与原始成功率共同报告；
- 无重试规则保护统计完整性，也会把基础设施故障计入结果，因此执行前的独立 preflight 尤为重要。

## 4.15 本章小结

本研究以阶段状态机、新鲜种子防火墙、规范路径与哈希闭包、单次打开解析、正进展时钟屏障、原子 journal、直接计数、确定性 assessor 和失败保全构成实验完整性方法。该方法把“运行成功”“证据完整”和“论文可宣称”分成不同判定，并为最后一轮性能实验预先限定了不能事后修改的统计与结论边界。
