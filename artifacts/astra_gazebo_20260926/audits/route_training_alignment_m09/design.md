M09: reuse the deployed sensor pipeline, replace the historical training backend
===============================================================================

The smallest useful implementation is a new injected environment/collector around `RouteTracksRuntime` and `TrackSensorBuffer`. Reuse `SensorActor`, `AsymmetricActorCritic` and PPO loss mathematics. Do not inherit `BenchmarkSensorCandidateEnv`, `PPOTrainer.__init__`, its seed/reset/rollout collection, or the old privileged-ranking environment. Those implementations create a Python kinematic/raycast world, not Gazebo transitions.

The old benchmark has four template families; M09 needs the six frozen core families and geometry-disjoint train parents. Its artificial six-frame startup history, 0.25 s scan increments, circle raycasts, forced-valid stop mask, spatial 0.4 m/s tier, 0.48 rad steering / 0.80 rad/s slew, and additional route-commitment priors differ from M08. M08 uses real exact-TF scans, six integer 200 ms buckets, actual base/rear/joint state, full nine-part geometry, spatial 0.6 m/s, 0.4964 / 0.75, 0.33 m margin and potentially all-false masks. Matching 6×72/10/8×7 array dimensions is insufficient to reuse a checkpoint.

Proposed modules, to implement in a new source revision:

- `route_training_environment_m09.py`: injected backend and exact M08 core. `reset(EpisodeSpec)` obtains a fresh environment identity and real sensor warmup, then returns a context only after the shared formal gate. `step(ProposalReceipt)` runs five nominal 50 ms controls until the next 250 ms decision, collecting every actual command/drop/source stamp and authoritative shared terminal. It never synthesizes a sensor history or uses the core rollout as an actual Gazebo transition.
- `gazebo_training_backend_m09.py`: uses the reviewed spawn/unpause/pause/recorder lifecycle, separate train stage contracts and persistent episode accounting. One worker initially; future parallel workers require isolated Gazebo/ROS ports and resource qualification. Actual `/scan`, exact TF, `/odom` and actual joints feed the same M08 input adapter. Model/link truth is available only to reward/critic/evidence consumers in a separate process or typed channel.
- `sensor_replay_alignment_m09.py`: replays train-only raw packets through the same core and checks exact history/source, candidate, normalized-feature, prior and mask parity. This is observation/interface testing or labelled supervised data, not an interactive RL environment. It must reject `step(new_action)`; an old logged actor response is not a counterfactual response to a newly chosen action.
- `route_ppo_collector_m09.py`: injects environments and an explicit collision-audited episode schedule; records latent sampled action/log-probability, post-advantage-gate action and all actual executed 20 Hz commands separately. It may reuse PPO clipping/GAE math after adapting transition validity and source-time intervals. It must not call the old constructor that silently creates proxy environments.
- `export_route_actor_m09.py`: exports only the actor inside `astra_route_tracks_sensor_actor_m08_v1`, with `astra_route_tracks_observation_m08_v1`, exact M08 semantics SHA, fixed feature shapes, new initialization and train-stage provenance. All five initializations are fresh. Old V5/V6/R2/benchmark weights and optimizer state are rejected.

Policy sampling must retain its actual probability model. During training call the same `SensorActor.choose_actions(deterministic=False, advantage_gate_margin=0.10)`; its returned `learned_action` is the latent categorical sample, while the returned final choice is after the residual gate. Record log-probability of the latent sample from the same logits. Shield changes and command drops are environment responses to that proposal, not reasons to relabel its probability as that of the executed action. An all-false hard mask triggers zero/model-backup handling and no policy-gradient sample; do not create a uniform categorical distribution from eight −1e9 logits. A timed-out actor has no eligible policy-gradient receipt. Every resulting delay, zero command and task failure remains in the episode/evaluation records; value/reward handling is explicit rather than silently deleting inconvenient outcomes.

Use actual source-time delta for reward/time accounting. The existing reward coefficients can be the first preregistered candidate: route-arc progress −0.30×elapsed seconds −0.01×absolute speed change −0.005×executed switch, +8 goal, −30 contact, −4 22 s timeout. This is a proposal, not a frozen reward contract. Treat goal/contact/horizon as finite-horizon terminal states; measurement/transport failure is a distinct infrastructure terminal with retained accounting and no fabricated transition. If variable decision durations are retained, use declared time-adjusted discount/GAE rather than silently assuming every decision lasted exactly 0.25 s.

The minimal first learner uses an asymmetric critic but no privileged rank target. A separate 48-field critic vector can contain three actors×12 source-stamped current truth fields plus 12 shared current fields; it never enters the policy dictionary, actor forward call or exported actor. Keep critic joins at-or-before the decision, with an explicit presence mask and no future source state. The actor receives exactly the five deployment keys. Old `privileged_distillation.py` chooses side from scene/actor truth, and `benchmark_training.py` substitutes a proxy oracle clearance; neither label is an execution-feasible Gazebo counterfactual. M10 labels require separately reviewed cloned/common-prefix interventions before use. M08's CV/retained occupancy remains uncalibrated; this ranker training does not create a learned candidate-conditioned interaction predictor.

Training support follows frozen `splits.yaml`: initial 100 parent geometries per family (600 total), all near duplicates/rigid transforms/actor cells grouped, fresh train episode namespace 261000000–262999999, and five proposed initialization seeds 260927001–260927005. Those five are absent from the current registry query, but this is not a reservation or exhaustive history audit. Each seed samples all six families; no seed-to-family confounding. Existing N04 development geometries/outcomes must not become training episodes. The full train catalog, allocation audit, new train episodes and compatible dependency environment remain prerequisites. Total steps and worker count must be frozen after hardware/storage and bounded collection throughput qualification; do not inherit the old 250000×12 defaults.

Maintain three explicit evidence regimes: `fast_proxy` may debug optimization or pretrain only under its own declared checkpoint provenance; `sensor_replay` tests/uses recorded sensor observations but cannot generate new action consequences; `gazebo_train` alone counts as actual Gazebo closed-loop training. Their step and episode counts remain separate. A proxy-trained actor still needs fresh sensor-domain Gazebo adaptation/evaluation and cannot be labelled Gazebo-trained from a shared class name.

Before fitting, compare exact fixed-input candidate/mask/normalization output and inspect genuine scan return/dropout/delay, odometry lateral slip, joint lag, mask cardinality, fresh-input ages and deadline/drop distributions on train-only qualification episodes. Do not tune gates to make them pass. After fitting, evaluate all five seeds on the same locked geometry-disjoint validation tranche, every family for every seed, all failures retained; apply M09's frozen interface-equivalence and ≥3% across-seed benefit/no task-or-safety regression rule plus the common mechanism promotion rules. Single-deployment-model choice uses the already frozen safety/completion/failure-inclusive-time rule. Final outcomes remain unopened until the separate final freeze.

`interfaces.py` is a stdlib-only typed/validated draft with six small passing guard tests; it starts no simulator or training and allocates no identities. Actual environment, collector, reward contract, teacher, calibration and checkpoint implementation remain future work. M08's measured full-chain 69.239986 ms negative and runtime dependency incompatibility remain visible prerequisites; no training wrapper may hide these delays by pausing simulation or replacing actual execution with its predictor.
