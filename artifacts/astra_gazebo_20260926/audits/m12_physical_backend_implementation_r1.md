# M12 physical backend R1 — implementation ready for independent build/review

New source is frozen at the bindings in `m12_physical_components_review_r1.json`. The isolated plugin only applies bounded joint efforts; actual body motion and joint states come from ODE. No ROS/Gazebo server was started by this agent. Root performs the linked build and fresh live qualification.

R1 fixes two demonstrated problems before execution. First, timeout/brake/emergency/fault no longer track a residual positive speed target: each clears PI integral and applies bounded torque opposing measured wheel rotation. At zero rotation the torque is zero. Internal reference deceleration remains bounded, but physical deceleration is not thereby qualified. In particular, changing only maxBrakeDeceleration will not change this passive torque law; later physical brake-strength stress needs an explicit preregistered torque mapping/version.

Second, Gazebo SDFormat9 silently dropped wheel friction extensions for the inherited named collisions. Four isolated conversion variants established that unnamed wheel collisions retain the extensions; this matches the [SDFormat documented named-collision bug](https://sdformat.org/tutorials/specification/sdformat_urdf_extensions/). The new m2_physical_base.xacro copies original model geometry/inertia/joints and removes only the four wheel collision labels. Both mu1=mu2=1 and 0.4 now produce four real SDF friction surfaces with fdir1=(0,0,1), aligned with the cylinder axle. Geometry/inertia/joints compare exactly after ignoring these labels; mass remains79.6kg before/after fixed-joint reduction. Runtime friction effects remain untested. New converted names are *_wheel_link_collision, so collision association must use the actual roster.

Base pose/twist nonfinite values fault the episode, invalid odom/TF are not published, singular steering configuration is rejected, and requested speed/steer envelopes are checked against real joint limits. Defaults reach25.22963rad/s versus wheel limit30 and front steering0.625451rad versus limit0.7446. reset_odom only rebases the report frame at linear/angular speed<=0.05, otherwise invalidates the episode.

Actual odometry uses base_link.WorldPose(), relative to the Load-time base_link pose. The current base rotation transforms Link.WorldLinearVel() and WorldAngularVel() into body coordinates, including vy. Gazebo Link.hh documents this velocity at the link origin, distinct from WorldCoGLinearVel. Dense comparison must use base_link, the same source stamp and the same body rotation. Actual joint_states are measured; actuator_target contains the four named references applied at the preceding Begin and published with corresponding End state at50Hz. Commanded effort is separately named and not misrepresented as reaction wrench.

The standalone component test covers25 forward/reverse/zero wheel geometries, bounded PI/PD/antiwindup, stopping counterexample/passivity and6000 reference-limit updates. Syntax-only C++14 build and XML/SDF parser checks pass. Actual acceleration, steering slew, braking, contact dynamics, friction response and candidate rear-axle integration require fresh live qualification. Old reviews, original failed friction conversion and old robot inputs remain preserved.
