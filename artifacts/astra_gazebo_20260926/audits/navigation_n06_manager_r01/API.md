# N06 manager r01: zero-authority implementation

This directory implements future exact-release execution; it does not create a release, reserve a seed, or authorize ROS. The eight prepared identities remain immutable. Proposed seeds 263003001–263003004 are not registered by this component.

## Entrypoints and control authority

- `workspace/scripts/astra_gazebo/run_navigation_n06_manager.py`: default prints zero authority. `--verify --release PATH --release-sha256 SHA` reads/rechecks only. A future `--execute` starts a direct-argv supervisor/worker pair only after a separately reviewed exact release and root's exact seed reservations. No prepare/retry/resume command exists.
- `navigation_n06_integrity.verify_release`: parses duplicate-free, finite JSON, checks closed authority/type, all path/SHA resources, exact prepared identities/rendered launches, source/native/passive/runtime/conversion prerequisites. `VerifiedSession.recheck` rehashes release and every bound resource before each unit and around assessment; a drift permanently closes the session. It does not enumerate unrelated future workspace files.
- `navigation_n06_process.cleanup`: real process ancestry + child nonce + start ticks, then pinned Linux pidfd signaling. No process-group signal is used. A disappearing or zombie child is benign; a still-live unverifiable identity fails integrity without being signaled. Supervisor and worker are subreapers. Roslaunch and assessment child environments carry per-unit markers. The separate `cleanup.json`, `cleanup_after_assessment.json`, and `cleanup_supervisor.json` preserve all phases.
- `navigation_n06_admin_plan.publish_plan`: constructs a new durable plan directory from terminal ledger/receipts and the three original CSVs. It never changes those CSVs. `apply_reviewed_plan` is a separate explicit API requiring an exact independent terminal/plan review. The manager never calls it.

## Durability, failures and administrative projection

A unique `supervisor_start` consumes the one-shot stage start. A durable event records each identity as consumed before any world launch. Immutable sequence events contain full state and a hash-chain link; the ledger is a replaceable pointer. A crash after event fsync but before pointer publication can be reconciled from the newest immutable event. Supervisor reconciliation writes infrastructure-only missing receipts, never guessed physics outcomes. Task timeout or safety-negative evidence with valid capture does not stop the matrix; an infrastructure failure retires all unrun units. No retries or replacement identities exist.

Three facts remain separate: worker function return; supervisor's `Popen.wait` observation of that child; outer host-shell status. The last always remains `unknown` here. A spawn failure has no observed child returncode. An already complete negative ledger is not rewritten merely because its worker correctly returns 3. N05's old outer 143 cause remains unknown.

The three administrative CSVs are specifically the canonical stage `seed_registry.csv`, `run_manifest.csv`, and `EXPERIMENTS.csv`; same-named files elsewhere are rejected. A complete plan directory is published atomically on its own filesystem. The three original CSV paths are **not jointly atomic**. Durable before/after snapshots and SHA, per-target rechecks, progress, and completion provide deterministic roll-forward after a partial replacement. A completed identical apply is a byte/inode/mtime no-op. Unknown third versions, changed receipts, incomplete independent review, wrong stage paths or mismatched ledger totals fail closed. Root must remain sole writer; the plan lock cannot coordinate unrelated writers. No automatic rollback hides a partially published after-version.

Known limits: Linux x86_64 pidfd/subreaper behavior is supported and locally component-tested; no live Gazebo episode/signal drain is qualified here. Exact source/runtime bytes are rechecked around use but no adversarial same-account race or immutable-memory theorem is claimed. Disk, kernel or supervisor failure can prevent a final durable artifact; unobserved exit/uncertain ownership must remain unresolved integrity failures rather than fabricated clean termination. A fully reviewed real release/native conversion/runtime closure and live qualification remain pending.
