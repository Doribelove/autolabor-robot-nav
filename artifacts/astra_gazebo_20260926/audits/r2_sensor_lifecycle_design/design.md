# Frozen R2 sensor lifecycle adapter — offline design

A separate `frozen_r2_v060_sensor_lifecycle_v1` identity can remove simulator truth from the outer lifecycle while keeping the R1/R2 runtime, eight candidates, mask, inference weights and control loop unchanged. It cannot turn that algorithm into a general fixed-polyline consumer. `design.json` binds the inspected source bytes, exact method locations, proposed override whitelist and acceptance cases. No runtime file, seed, release or checkpoint was created.

The existing wrapper only replaces readiness/warmup. Inherited `execute_sensor` still calls `robot_world_pose → common_metrics_step → goal_state` before action generation, so true model position can terminate it. Actor true positions also enter diagnostics in the control loop. The new adapter must derive pose/path/goal lifecycle from source-stamped odometry and the shared coordinator, omit model/contact subscriptions and Gazebo services, and move physical clearance/contact truth entirely into the independent evaluator. Its top-level report must not inherit old `scientific_inclusion=True` or interpret absent contact counters as measured zero contacts.

The constructor needs an audited transport-only derivation because the parent does not retain the model subscriber handle; calling the old constructor and pretending a no-op callback removes the subscription is inadequate. Keep the actor/runtime initialization block and R2 variant application numerically identical. Validate positive, ordered sensor timestamps before invoking unchanged callbacks, hold small future transport until the local clock covers its source, and retain the .20 s health bound. Readiness must count six successfully appended distinct scan sources: the parent initializes a6×72 padded array, so `len(scan_history)==6` is not evidence of six real histories. The old float-based .20 s sampling remains frozen; replacing it with integer buckets would require a separately disclosed observation-semantics version.

Shared route availability can be audited by a complete path/hash receipt, but the receipt must declare `route_use=audit_only`, `full_polyline_consumed=false`. The R2 generator uses absolute x-dependent lateral targets and terminal features. Frenet warping, changing candidate targets, guide-based mask/ranking, or manufacturing map corridor barriers would change the algorithm. A strict straight-route adapter is possible only when the entire guide already equals the canonical monotone x-axis with the same endpoints; bent or blocked guides must reject before allocation. That narrower claim cannot quietly replace the six-family population.

The honest general-layout comparison keeps this frozen R2 as an explicitly limited auxiliary/context comparator alongside the four route-consuming methods. This alone does **not** fulfill a strict five-primary-method shared-path requirement. A fifth full-route comparator needs its own algorithm/checkpoint identity, or the claim/population must be explicitly revised. The old model must never be relabelled as a trained route-aware policy.

Keep the shared coordinator's actual gate/terminal clock authoritative, and retain the inherited algorithm's local elapsed feature origin as a disclosed behavior. Stream completed decision/control records before terminal pause instead of depending on its final six zero/sleep tail. Headerless private Twist receipt remains insufficient to prove generation time; an eventual source/gate-bound publication envelope must be separately reviewed and cannot be asserted retroactively for actual TEB/DWA.
