# B03 independent offline review

The frozen B03 source package passes this bounded source and fake-transport review. All 27 author tests replayed successfully; 9 additional independent tests passed. All 39 author-manifest resources match their saved hashes. No B03 source was changed, and no ROS master, Gazebo, build, training, seed, or release was started. Live qualification remains pending.

The adapter uses the original `odom` / `base_link` message as its input. The fixed rear point is `(-0.325, 0, 0)` in the base frame: its position is transformed with the full pose rotation, and its velocity is `v_base + omega × r` in the unchanged body axes. Real rear lateral velocity, angular velocity, source stamp, and covariance are retained. Independent tests used serialized ROS messages, nonzero roll/pitch/angular velocity, and a nonidentity map transform; the input message bytes were unchanged. This agrees with the P05 driver's relative-origin odometry and body-twist convention. It does not introduce a world-frame rotation into a body command.

Future source stamps are queued until visible, without retiming. Duplicate/regressed source stamps, invalid quaternions, excessive tilt, source expiry, and backward clock observations fail closed. A second fresh-clock check protects each publication. Zero-time data cannot establish readiness. The independent tests retain the actual 2 ms odometry-versus-clock delay in both actual coordinator `main()` paths.

There is one intended static rear TF edge, `base_link -> rear_axle_kinematic`; no competing `odom -> rear` parent is introduced. The adapter subscribes to odometry and the two TF channels, without Gazebo truth or command publication. Foreign/wrong rear TF and publisher identity checks are present. Graph checks are periodic and trusted-process checks, not an instantaneous transport-security proof.

GetPlan accepts map-frame poses, converts the rear start back to the original base reference for the unchanged 2 m route-distance check, and checks the inverse-transformed goal. It returns the complete original oriented guide transformed point by point, including the explicitly declared final goal yaw. It does not insert, prune, smooth, or replan. Map/odom frame confusion is rejected in the tests. Geometry-request header stamps are not used as sensor freshness evidence; the service separately requires current actual odometry. The transformed oriented poses represent the same physical configurations, but their connecting chords need not equal a simple translated path at heading kinks, and no Ackermann path-feasibility proof follows.

The common coordinator's two classes are AST-identical to N02; the module method roster is new. Actual base odometry still owns activation, the common gate, the 22 s deadline, and the first base-goal arrival at 0.25 m / 0.25 rad. A private move_base success callback is diagnostic only. Independent fake transport injected private success before actual base arrival under a map translation `(2, -3)` and yaw `0.7`: both methods remained active, sent the correctly rotated rear goal, preserved the body command, and terminated at the later first qualifying actual odometry stamp.

Both costmaps' existing padded 64-point polygons and TEB's existing raw 16-point polygon are translated by exactly +0.325 m in the new rear coordinates, with zero added padding. XML inspection confirms the B03 overlay loads last and remaps odometry and commands to the intended topics. Both methods use internal 0.15 m / 0.10 rad goal tolerances; DWA's XY latch is disabled. The common-pose base-position upper bound is `0.15 + 2*0.325*sin(0.10/2) + 0.325*(1-cos(0.05)) = 0.18289262539757686 m`, inside the shared 0.25 m ball. Actual TEB source and saved official DWA stop/rotate source support the current-pose interpretation. This is geometric set containment, not a guarantee about asynchronous callback order. DWA's inherited `acc_lim_y=2.5` is unchanged; rear slip is not erased and stop/rotate remains an Ackermann limitation.

One partial-evidence boundary must be carried into integration: `publish_pending()` drains a batch before publishing each row, and the caller writes diagnostic receipts only after the function returns. If row one is published and row two expires before publication, the stream permanently faults, but row one's already-published rear odometry can lack its diagnostic receipt. The independent expiry fixture reproduces the partial publication and permanent fault. The author acknowledged this boundary. A future collector must preserve the partial output and missing receipt as an integrity failure; it must not fabricate a receipt or assert blanket one-to-one completeness for a failed run. This does not permit a passing B03 execution.

This is a reference-frame and goal-integration engineering package with several explicit changes, not an isolated single-factor performance comparison. It does not retrospectively change old TEB/DWA results. Yaw-only costmaps are not exact projections of tilted 3D geometry: the previously retained 0.00040616537 m example remains a margin-review prerequisite. Actual launch expansion, interpreter/ELF closure, compatible collector and actor identities, recording of all rear/TF/path/status/action-result evidence, real planner consumption, and physical behavior must be qualified in a fresh bounded stage. The XML/static tests here are not an actual roslaunch preflight.
