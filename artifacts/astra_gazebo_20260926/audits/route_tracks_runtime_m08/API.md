M08 review-frozen interface
===========================

`astra_route_tracks_runtime_m08.py` is a new simulation method node. It subscribes only to `/scan`, `/odom`, `/joint_states`, `/map`, `/astra/common_route/path`, `/astra/navigation/gate` and `/astra/navigation/status`. It publishes headerless Twist only on `/astra/method_cmd`; the shared coordinator remains the sole `/cmd_vel_navigation` authority. It does not call Gazebo services. A new stage must explicitly add the M08 enum to a new coordinator/launch; frozen N04 is unchanged.

Required private parameters: `run_id` (string), `seed` (positive integer matching actual URDF dynamicsSeed), `method` (`astra_analytic_route_tracks_m08` or `astra_pct_route_tracks_m08`), `bundle` (directory), `bundle_sha256` (common_route.json bytes). Environment requires a loopback ROS master, `/use_sim_time=true`, `/m2_gazebo/simulation_only=true`, `THESIS_WS`, actual `/robot_description`, and an exact-source map←laser TF. The PCT enum additionally requires `checkpoint_metadata` and its `checkpoint_metadata_sha256`; its artifact must use `astra_route_tracks_sensor_actor_m08_v1` with observation schema `astra_route_tracks_observation_m08_v1`, exact core semantics SHA and new training provenance. No such checkpoint has been created; old route/R2 artifacts are rejected.

The node name is `/astra_route_tracks_runtime_m08`. It advertises `/astra/route_tracks_m08/start` and `/astra/route_tracks_m08/stop` (Trigger). Start is consumed once and requires the matching shared gate, six real history rows, fresh sensor joins, exact map/path, and unique method-topic publication. It also starts automatically after the gate. Shared terminal status supplies the task outcome; the node zeros at the declared deadline while awaiting that authoritative outcome. Later local faults cannot replace a received terminal outcome.

Latched identity/status topics: `/astra/route_tracks_m08/identity`, `/astra/route_tracks_m08/status`. Recorded event topics: `/astra/route_tracks_m08/trace`, `/astra/route_tracks_m08/candidates`; shared readiness/activation acknowledgements: `/astra/method/status`. Record all alongside shared coordinator, actual sensors, physical targets/status and evidence streams. Twist contains no source header: the trace timestamp denotes the local prepublish check, not downstream command receipt or a fabricated generation header.

Pure core entry points are `RouteTracksRuntime.accept_scan`, `build`, `select`, `command`, `transaction`, and `future_prediction_request`. The latter exports actual eight rollouts and six accepted scan hashes for future candidate-conditioned learning/calibration; it is not a fitted predictor and cannot replace hard occupancy. `TrackSensorBuffer` supplies exact-TF scan ingestion with latest actual odometry at-or-before each scan, exact odometry/joint state joins, and separate six-by-72 real 200 ms history. Actual base lateral velocity is retained and converted to the rear-axle reference; actual wheel steering positions are used. Full base collision envelope and terminal base goal remain inherited.

`build` retains the eight action identities, speed/offset tiers and inherited state/step/rollout functions. Tracking changes clearance, analytic prior and mask values, so normalization layout alone does not justify reusing old weights. The new schema binds all relevant new helper sources, map/route and physical backend identity. Future training must call the same core without copying its candidate or mask logic.

Twenty-millisecond actor expiry discards that private inference job; a current verified analytic choice may run if the total budget still permits. Total transaction >50 ms, stale/future input or failed current backup check yields zero and commits action 0. Every 20 Hz control tick checks its backup against current occupancy. These are output guards, not hard real-time or physical safe-stop guarantees: Python/ROS/GIL scheduling can delay zero publication itself. Final measured sparse re-observation + retained-support workload reaches 69.239986 ms, so full deadline and live qualification remain false. See implementation_report.json and benchmark_frozen.json for retained negative timings and source bindings.

Next integration requires a fresh bounded research stage, independently reviewed coordinator/collector/recorder bindings and actual runtime-library closure (including scipy.spatial cKDTree). No seed, release, build, simulator execution or training is supplied by this component delivery.
