# P02 source-stamped physical status

New `astra_physical_ackermann_p02_plugin.cpp`, `m2_physical_p02.urdf.xacro`, `m2_physical_p02_gazebo.xacro` and `spawn_m2_physical_p02.launch` are independent files. The P01 plugin remains8b5d45c0. The new target/library is astra_physical_ackermann_p02_plugin / libastra_physical_ackermann_p02_plugin.so; add diagnostic_msgs to catkin/package dependencies. No build, ROS master or Gazebo server was started by this agent.

At each50Hz WorldUpdateEnd publication, `/m2_driver/physical_status` carries one DiagnosticStatus with name astra_physical_ackermann, hardware_id simulation-only, precedence ERROR for fault, WARN for timeout, otherwise OK. backend_fault/command_timeout/brake/emergency values are literal true/false strings. Header.stamp is the same single current simulation source time used by odom/joints/targets, and publisher queue is1000. Legacy Bool topics remain diagnostic evidence; receipt spacing is not source spacing.

A finite source time with invalid base/joint data emits Bool fault plus stamped ERROR status and returns without fabricated motion measurements. Nonfinite, negative or unrepresentable source time faults and logs source_status_omitted=true; it never substitutes receipt/wall time or a fabricated zero stamp. This clock validity check is publication hygiene. The simulation control law, integration, parameters, gains, limits, callback behavior and all original physical telemetry values remain unchanged at valid source times.

`m12_p02_plugin_source.diff` records the exact change. Three static tests prove that removing the explicitly allowed telemetry additions and class rename recovers the entire old C++ byte-for-byte; model/launch changes are restricted to entrypoint names; expanded URDF canonical trees are identical after renaming the single driver plugin. This is stronger than merely comparing a selected control function. Compilation and source-stamp coverage are pending root build and the independent P02 fixture. P01 remains preserved and is not rerun.
